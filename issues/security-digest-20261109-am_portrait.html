2026년 11월 9일자 월요일 아침 다이제스트. 오늘 네 건은 모두 '남을 믿는 지점'에서 터졌다 — 외주 클라우드(AIris Oyama), AI 도구 설정 파일(Claude Code), 레거시 결제 인프라(Gnosis Pay), 민간 위탁 개발사(대구로). 각 사안은 회사 공식 발표·보도 단계이며, 아이리스 오야마는 BleepingComputer·MLQ.ai, Claude Code는 Apiiro 연구(Cyber Recaps 보도), Gnosis Pay는 공식 공지·Bitcoin.com, 대구로는 경북일보·오마이뉴스 보도 기준으로 정리했다.

Top Story 1

아이리스 오야마 —
외주 클라우드에서 770만 명이 새다

회원 580만 + 비회원 주문자 190만 · 성명·주소·전화·이메일·생년월일·암호화 비밀번호
공식 발표 내용
  • 일본 생활용품·가전 제조사 아이리스 오야마는 11.8 온라인 쇼핑몰 '아이리스 플라자'가 연동하는 제3자 외부 클라우드 서비스에 비인가 침입이 발생, 최대 770만 명의 고객 정보가 유출됐을 가능성을 공식 발표 — 10월 28일 클라우드 환경에서 악성(의심) 파일 감지 직후 쇼핑몰 접속을 차단하고 일본 개인정보보호위원회(PPC)·사법당국에 신고했다(BleepingComputer 보도)
  • 유출 항목: 성명, 배송지 주소, 전화번호, 이메일, 성별, 생년월일, 단방향 암호화 비밀번호 — 회원 약 580만 명과 비회원 주문자 약 190만 명의 주문·계정 DB에 비인가 접근이 확인되었다(MLQ.ai 분석). 신용카드 정보는 외부 결제사 처리로 클라우드에 보관되지 않아 제외
  • 침투 지점이 자사 IDC가 아니라 외주 클라우드 서비스(SaaS/PaaS)라는 점이 핵심 — 일본에서는 지난 다이이치코쇼 860만 명 유출에 이어 B2C 대규모 침해가 연쇄 발생 중이며, 벤더측 설정 오류·접근 통제 미흡이 원인으로 지목되고 있다
출처BleepingComputer · MLQ.ai 분석 · 아이리스 오야마 공식 발표

'우리 데이터는 클라우드에 있으니 안전하다'는 명제는 이제 성립하지 않는다 — 데이터가 아니라 그 데이터를 다루는 남의 운영을 신뢰한 셈이다. 서드파티 벤더 침투 테스트·최소 권한 감사를 계약 조건으로 강제하지 않는 한, 자사 보안 등급은 벤더 중 가장 약한 고리의 등급이다.

Top Story 2

Claude Code 자동 승인 —
편의 한 줄이 평문 유출통로가 됐다

Apiiro 연구 · GitHub 공개 저장소 1,122곳 · 유효 비밀 1,379개 · AI 공급망 리스크
유출 메커니즘
  • 개발자가 대화형 세션에서 "Yes, and don't ask again"으로 셸 명령어를 영구 승인하면, 명령어 문자열 전체가 .claude/settings.local.json에 기록된다 — 명령 안에 들어 있던 DB 접속 정보, 클라우드 API 키, SSH 자격증명이 평문 그대로 저장되는 구조다(Cyber Recaps 보도, Apiiro 연구)
  • 설계 결함의 두 번째 고리: Claude Code가 이 파일을 프로젝트 루트의 .gitignore가 아니라 로컬 .git/info/exclude에만 등록 — exclude는 클론·푸시 시 이전되지 않으므로, 개발자나 AI 에이전트가 자동 커밋·푸시하면 파일이 GitHub 공용 저장소로 함께 올라간다
  • 연구진 스캐닝 결과 1,122개 공개 저장소에서 AWS 시크릿 키, 프로덕션 DB 패스워드 등 1,379개의 유효한 비밀 자격증명이 평문 노출된 것으로 확인 — 노출된 키는 즉시 무효화가 필요하며, 커밋 이력까지 정리해야 한다
출처Apiiro 연구 · Cyber Recaps 보도

last-mile 실수의 전형: 로컬 exclude는 '내 컴퓨터에서만 숨김'이지 저장소 밖으로 내보내지 않는 장치가 아니다. AI 코딩 도구가 커밋·푸시까지 자동화되는 시대에는 도구 설정 디렉터리(.claude/ 등) 전체를 글로벌 .gitignore에 넣는 조직 정책이 필요하다. 이번 주 국내 '대구로' 외주 사고와 같은 문법 — 신뢰한 도구가 통로가 된다.

Top Story 3

Gnosis Pay —
지갑은 지켰지만 익명성을 잃었다

레거시 카드 인프라 침입 · 카드번호·청구지·온체인 지갑 주소 1:1 매핑 노출 · 12.20 레거시 폐기
침해 양상과 위험
  • 암호화폐-Visa 실물 결제 연결 서비스 Gnosis Pay가 구형 소비자 결제 카드 시스템에 대한 비인가 접근을 탐지, 고객 결제 카드 정보와 온체인 지갑 주소가 연결된 민감 데이터 유출을 공식 인정했다(공식 공지) — 공격자는 일부 마스킹된 카드 번호, 청구지 주소, 암호화폐 지갑 주소를 추출했다(Bitcoin.com 보도)
  • 온체인 자산 자체는 안전하고 3D Secure도 활성화됐으나, 진짜 피해는 탈익명화(De-anonymization) — 공개 블록체인 상의 지갑 주소에 실명·주소·오프라인 소비 이력이 1:1로 결부되면서 지갑 잔액과 실물이 연결됐다
  • 2차 범죄 벡터: 암호화폐 보유자가 자산 규모를 아는 공격자의 표적 피싱·물리적 갈취(5달러 공격)에 노출 — 회사는 해당 레거시 시스템을 12월 20일 완전 폐기로 대응했다
출처Gnosis Pay 공식 공지 · Bitcoin.com 보도

'자산 안 털렸다'는 발표와 '프라이버시 파산'이 동시에 성립하는 사건 — 웹3의 익명성은 주소-신원 분리에만 존재하는데, 결제 규제·실명 절차가 그 결합을 강제하고 레거시 인프라가 그 결합본을 보관해 온 셈이다. 식별 데이터와 지갑 주소의 분리 보관 규제가 입법 이슈로 부상할 사안.

Top Story 4

대구로 해킹 —
위탁사 구멍이 공공 신뢰로 번진다

가맹점주 계좌번호 2만 5,000여 건 유출 · 11.8~27 시 본청·산하 20여 개 기관 특별점검
사고와 파장
  • 대구광역시 공공 배달·택시 플랫폼 '대구로'가 해킹되어 가맹점주 정산용 계좌번호 2만 5,000여 건이 유출된 사고와 관련해, 대구시가 11월 8일부터 27일까지 시 본청 및 산하 공사·공단·출자출연기관 20여 곳을 대상으로 사이버보안 특별점검에 착수했다(경북일보 보도)
  • 점검 범위: 정보시스템·웹서비스 전체의 웹 취약점, 비인가 접근 통제, 계좌번호 등 금융 식별정보 암호화, 그리고 외주 위탁 운영사의 보안 관리 실태 전수 재검증(오마이뉴스 보도) — 사고 원인이 공공 플랫폼을 위탁 운영하는 민간 개발사의 보안 취약점으로 지목되면서 지자체 전반으로 점검이 확대됐다
  • 공공 서비스의 '민간 위탁 + 상시 온라인' 구조가 전국 공통이라는 점이 파장의 크기 결정 — 유사 배달·택시·예약 플랫폼을 운영하는 타 지자체·공공기관도 동일 취약면을 공유한다
출처경북일보 · 오마이뉴스 보도

계약서상 '보안 관리' 조항과 실제 통로 감사는 다르다 — 위탁사에 모의해킹 검증 결과와 접근 통제 증적을 요구하지 않으면, 지자체의 보안 등급은 개발사 한 곳의 실력이다. 다우오피스·대구로로 이어진 국내 공급망 침해 계열의 이번 주 버전.

Deep Dive 1

구조 분석 —
네 사고에 공통으로 남은 한 줄

해석 프레임
  • ①피해는 '내가 지킨 경계'가 아니라 '남이 운영하는 경계'에서 난다 — 아이리스 오야마(외주 클라우드) / Gnosis Pay(레거시 인프라) / 대구로(위탁 개발사) / Claude Code(AI 도구 설정) : 네 사례 모두 조직 경계 바깥의 신뢰 지점이 침투 통로였다 : 보안 경계의 정의가 방화벽에서 계약서·설정 파일·레거시 자산 목록으로 확장됐다
  • ②'숨김'과 '격리'를 혼동한 대가 — Claude Code의 .git/info/exclude(로컬 숨김)는 저장소 밖 이동 시 소멸한다 / Gnosis Pay의 카드 마스킹(표시 숨김)은 지갑-신원 결합을 막지 못했다 : 숨김은 표시 문제, 격리는 데이터 분리 문제 — 둘 사이 간격이 곧 이번 주 피해 규모다
  • ③레거시는 '미해결 사안의 대기실' — Gnosis Pay는 유출 직후 레거시 폐기(12.20)를 결정했고 대구로는 상용 서비스 이면의 위탁 운영 체계가 뚫렸다 : 쓰이고 있으나 관리되지 않는 자산이 공격자에게는 가장 조용한 진입로 : 자산 인벤토리에서 '방치' 플래그가 곧 취약점 우선순위다
출처각 사 공식 발표·연구 보고서 교차 독해

이번 주 키워드를 하나만 고르라면 '위임된 신뢰'다. 클라우드, AI 도구, 결제망, 위탁사 — 모두 효율을 위해 위임한 것들이고, 공격자는 그 위임 관계의 약한 쪽을 고른다.

Deep Dive 2

AI 도구 공급망 —
'생산성 기능'이 공격면이 되는 법

Claude Code 사례의 일반화
  • 패턴: 편의 기능(영구 승인) → 상태 저장(설정 파일 평문 기록) → 잘못된 격리 가정(로컬 exclude) → 자동화된 반출(AI 커밋·푸시) — 각 단계는 개별적으로 '버그'지만 사슬이 되면 1,122개 저장소 규모 유출통로 : AI 에이전트가 명령·파일·git을 모두 다루는 실행 주체가 된 순간, 도구 설정 파일은 평문 자격증명 저장소가 된다
  • 방어 원칙 — ①시크릿 스캐너를 커밋 훅·CI에 강제(pre-commit/gitleaks류), 평문 키가 저장소 경계를 넘는 순간 차단 ②AI 도구 설정 디렉터리(.claude/ 등) 글로벌 gitignore 정책화 ③자동 승인 기능은 허용 명령 패턴 화이트리스트로만 운영, 와일드카드 승인 금지
  • 노출 사후 절차: 노출된 키는 회전만으로는 부족 — 커밋 이력에서 완전 제거(git filter-repo 등), 접근 로그로 악용 흔적 포렌식, 공개 저장소 전수 스캔 정례화 : 지난주 WorkOS 교훈(에이전트 egress)과 이번 주 교훈(에이전트가 쓰는 자격증명 위생)은 같은 코인의 양면이다
출처Apiiro 연구 · Cyber Recaps · 지난주 에이전트 리스크 보도 맥락

개발팀이 오늘 확인할 단 한 줄: git 저장소 목록에서 .claude/settings.local.json(또는 동급 도구 설정)이 추적 대상에 올라 있는가. 올라 있어도 당장 비밀이 없으면 안전하다고 착각하지 말 것 — 영구 승인 한 번이면 채워진다.

Deep Dive 3

위탁·외주 보안 감사 설계 —
계약서가 아니라 통로를 본다

감사 프로토콜
  • ①목록화 — 클라우드 연동·위탁 운영·레거시 결제 경로 등 '남이 운영하는 데이터 통로' 전수 인벤토리: 어떤 데이터가, 어디에(평문/암호화), 누구 접근 하에 있는지의 3열 매트릭스 : 아이리스 오야마는 이 목록의 '외주 클라우드' 칸에서, Gnosis Pay는 '레거시 카드 인프라' 칸에서 터졌다
  • ②증적 요구 — 위탁사에 형식적 보안 서약서가 아니라 최근 모의해킹 보고서·접근 통제 로그·최소 권한 구성 증적을 정기 제출 요구, 계약 갱신 조건화 : 대구로 사고가 보여준 것은 '위탁했다'와 '지키고 있다' 사이의 거리다
