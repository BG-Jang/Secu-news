Top Story 1

PHP, 18개 취약점
긴급 패치 —
'phpAfterShell'이 열쇠

CVE-2026-126714 CVSS 4.0 9.2(Critical·NVD 확인) — 파일 세션 쓰기 중단을 노린 TOCTOU 역직렬화 RCE
  • PHP Foundation이 11월 19일(현지시간) 지원 중인 전 라인업(8.2.36·8.3.37·8.4.28·8.5.13·8.6.0)에서 RCE·세션 변조·로컬 권한 상승을 포함해 총 18개 취약점을 일괄 수정 — 그중 CVSS 9.2 치명적 결함 7종. 지난 10월 PHP2Shell 사태의 후속 격이라 워드프레스 계열 워프리그를 다시 흔드는 일정이다(The Hacker News·BleepingComputer)
  • Depthfirst가 'phpAfterShell'로 명명한 CVE-2026-126714는 파일 기반 세션(기본값)의 pwrite()·ftruncate() 쓰기 중단 찰나를 파고든다 — 새 세션 데이터 앞부분과 이전 세션 뒷부분이 한 파일에 섞이게 유도하면, 다음 session_start()에서 공격자 문자열이 유효한 직렬화 객체로 복원돼 RCE가 된다(NVD 원문: 'Partially overwritten session files can lead to remote code execution')
  • NGINX(fastcgi_keep_conn on)·Apache(mod_proxy_fcgi enablereuse=on) 지속 연결 환경의 php://input 불완전 읽기 RCE(CVE-2026-129289), 무인증 원격 코드 실행(CVE-2026-115560·129496), FPM 로컬 권한 상승(CVE-2026-129291)이 같은 배치 — 즉시 업그레이드가 답이며, 지연 시 session.upload_progress.enabled 비활성화·FastCGI 연결 재사용 제한이 임시 방패
출처NVD API(CVE-2026-126714) · The Hacker News · BleepingComputer

확정 vs 보도 구분: CVE-2026-126714의 9.2 Critical은 NVD 채점(CVSS 4.0, security@php 원채점) 원문 확인. '치명적 7종·총 18건'과 나머지 CVE 번호는 매체 보도 기준이며 개별 CVE의 NVD 레코드는 순차 생성 중이다. 세션 파일 뒤섞기(TOCTOU) 결함은 상태 조건이 아니라 쓰기 중단이라는 시간성 공격이라 WAF로는 못 막는다 — 버전 업데이트 외 실질 방어 없음.

테이블 하나 없이
OS 셸을 얻다 —
4대 DB 엔진 RCE 공개

Oracle Text(CVE-2026-114819, 벤더 채점 9.9·NVD 확인) + ORDS GraphQL 체이닝 — 로그인 없이 무인증 RCE 시연
  • 연구원 Zheng Yu(Depthfirst)가 11월 19일 PostgreSQL·MySQL·Oracle Database·ClickHouse 4종에 대한 RCE 익스플로잇 연구를 공개 — 핵심 전제는 '애플리케이션 테이블 조회 권한조차 없는 계정'. TEMPORARY 테이블 생성 권한 하나만 있으면 쿼리 파서·옵티마이저의 C/C++ 메모리 손상을 트리거해 DB 서버 OS 명령 실행에 이른다(The Hacker News)
  • 대상별 현황: PostgreSQL CVE-2026-116331(11월 12일 패치, min/max 집계 최적화의 타입 혼동 — NVD 현재 8.8 High·분석 대기), MySQL Server/Cluster CVE-2026-101786(10월 20일 CPU 패치), ClickHouse는 v26.9 및 백포트로 이미 수정 — 각 배포 시점보다 늦게 따라가는 관리 환경이 실질 표적이다
  • Oracle은 노출된 웹 엔드포인트에서 Oracle Text(9.9)와 ORDS GraphQL(CVE-2026-91609, 10월 CPU)을 체이닝해 계정 로그인 없이 RCE 도달 — DB를 '내부 자산'으로 취급하고 네트워크 노출을 방치한 구성이 이번 연구에서 가장 아픈 지점이었다
출처The Hacker News · NVD API(CVE-2026-116331·114819) · 사용자 브리핑

NVD 원문 대조: PostgreSQL CVE-2026-116331 설명은 'Type confusion in PostgreSQL min/max aggregate optimization allows an object creator to execute arbitrary code as the operating system user' — 점수는 현재 8.8 High(분석 대기)로, 브리핑의 '치명적' 프레이밍보다 낮게 매겨진 상태임을 병기한다. Oracle CVE-2026-114819는 secalert(오라클) 원채점 9.9 Critical 확인. 방어 지침: 최신 패치 + 앱 계정에서 TEMPORARY 생성 권한 회수 + ClickHouse format_binary_max_string_size 등 위험 옵션 통제.

Deep Dive 1

세션 파일은 어떻게
공격 코드가 되는가 —
phpAfterShell 해부

  • 직렬화 포맷이 본질: PHP 세션은 '키:{타입코드}:값' 형태의 문자열로 저장되고 session_start()는 파일 내용을 무조건 문법적으로 해석한다 — 쓰기 도중 앞뒤가 섞인 파일도 파싱만 통과하면 객체가 된다. 공격자는 새 데이터 Prefix와 옛 데이터 Tail의 경계를 조작해 '유효해 보이는 조각'을 만들어 넣고, 다음 읽기에서 그것이 살아나는 TOCTOU(확인-사용 사이 경쟁)를 노린다
  • pwrite()·ftruncate()가 중단되는 찰나 — 디스크 압박·신호·프로세스 종료 같은 '정상 장애'가 공격 창구가 된다 — 정상 트래픽에서는 희박하지만, 공격자가 동시 요청을 걸고 쓰기 실패를 유도하면 확률 게임이 공격자 쪽으로 기운다. 파일 세션 핸들러(기본값)가 표적이고, DB·Redis 세션 저장소로 옮겨둔 환경은 이 경로가 원천 차단된다
  • 지속 연결 불일치(CVE-2026-129289)는 제2의 전선: 애플리케이션이 php://input을 끝까지 읽지 않은 채 응답하면, 같은 커넥션의 다음 요청이 앞 요청 본문과 이어져 해석된다 — NGINX fastcgi_keep_conn on·Apache mod_proxy_fcgi enablereuse=on 환경에서 프록시와 백엔드의 '경계 인식 차이'로 RCE가 성립. request-Body 완독을 강제하지 않는 앱 코드 관행까지 함께 고쳐야 한다
출처NVD CVE-2026-126714 원문 · Depthfirst 명명 보도 종합

실무 지침 우선순위: ① 버전 업데이트(8.2.36·8.3.37·8.4.28·8.5.13·8.6.0) ② 파일 세션 → 저장소 이전(Redis·DB)은 이 클래스 전체의 구조적 해결책 ③ 임시: session.upload_progress.enabled=0, FastCGI 재사용 제한. 10월 PHP2Shell에 이어 두 달 연속 PHP 코어 패치 라운드가 열린 것 — PHP를 인터넷 경계에 세운 조직은 분기별이 아니라 월간 패치 리듬으로 전환할 시점이다.

Deep Dive 2

'최소 권한'의
새 정의 —
TEMPORARY 하나가 셸이 된다

  • Zheng Yu 연구가 무너뜨린 전제: DB 보안은 '무엇을 읽을 수 있는가'(SELECT·스키마)만 통제해 왔고, '어떤 코드를 실행시키는가'는 고려 대상이 아니었다 — 그런데 쿼리 파서·옵티마이저는 C/C++로 된 사용자 입력 실행 경로다. TEMPORARY 테이블을 만들 수 있다는 것은 곧 그 파서에 구조화된 입력을 보낼 통로를 보장받는 것이고, 파서에 메모리 손상 결함 하나만 있으면 권한 모델은 OS 셸 앞에서 무의미해진다
  • PostgreSQL CVE-2026-116331이 전형이다: min/max 집계 최적화의 타입 혼동 — '객체 생성자(object creator)'면 운영체제 사용자 권한으로 임의 코드 실행(NVD 원문) — 테이블을 읽지 못해도 임시 객체를 만들고 집계 경로를 태울 수 있으면 된다. 감사 로그 관점에서 이는 '정상 SQL'로 보이므로 탐지 규칙도 재작성이 필요하다
  • Oracle 체이닝이 보여준 조합: 내부 DB + 노출된 웹 엔드포인트(ORDS GraphQL) = 무인증 원격 코드 실행 — DB 보안과 웹 공격 표면의 경계가 조직 내부에선 팀 구분일 뿐, 공격자에겐 그냥 두 단계다. 네트워크 정책으로 관리·GraphQL 엔드포인트를 인터넷에서 회수하는 것이 패치만큼 급하다

패스키와 OAuth,
잠복이 되는 자격 —
클라우드 영속성 장악의 구조

비밀번호 초기화·세션 만료로는 IdP에 등록된 패스키·MFA 기기·OAuth 권한이 제거되지 않는다 — 전수 초기화가 대응의 1단계
  • 콜드렐릭의 시나리오는 3단 잠금 해제다: ① MFA 피로 공격으로 관리자 진입 ② 패스키·OAuth 앱 등록 = 비밀번호 바깥의 영속 자격 확보 ③ 탈취한 직원 명부(Takeout) 기반 메신저 사칭으로 두 번째 기관 침투, Entra ID SSO 토큰 탈취 — 각 단계가 서로 다른 신원 시스템(Google Workspace → 보안 메신저 → MS Entra ID)을 잇는 인간 신뢰로 연결됐다
  • '비밀번호 = 계정' 가정의 종말: 클라우드 IdP에서 계정의 정체성은 비밀번호가 아니라 등록된 인증 수단 전체의 집합 — 공격자가 등록한 패스키는 피해자가 비밀번호를 바꾸고 세션을 전부 만료해도 남는다. 실제 사고 대응에서 이 항목은 별도 절차·별도 감사 대상으로 다뤄야 한다
  • 더존비즈온 사건과의 대칭: 국내 공급망 침해(신뢰된 소프트웨어)와 글로벌 신원 침해(신뢰된 IdP)는 같은 교훈의 두 얼굴 — 내 통제 밖에 있는 '이미 신뢰한 것'을 정기적으로 재실사하는 절차(벤더 보안 점검·IdP 등록 수단 감사·OAuth 앱 allowlist)가 두 사건 모두의 공통 방어선이다
출처구글 맨디언트·GTIG 발표 · 보안뉴스 보도 종합

IdP 대응 런북 요약: ① 전 사용자 등록 인증 수단(패스키·FIDO2·앱 비밀번호·MFA 기기) 목록화 후 침해 의심 계정 전수 폐기 ② OAuth 앱 등록·서비스 계정 키 감사(미식별 앱 즉시 revoke) ③ Google Takeout·내보내기 API 사용 로그 역추적 ④ SSO 토큰 탈취 시 연결된 모든 스택 세션 토큰 무효화. 메신저 사칭 접점은 직원 대상 '보안 메신저 발신도 인증 요구' 정책으로 확장.
