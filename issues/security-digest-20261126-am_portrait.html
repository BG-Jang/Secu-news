미 재무부 금융정보망 비인가 접근 / 더존비즈온 53곳+ 돌파, 한국투자저축은행 8.6만 명
어제까지 '가능성'이었던 것들이 오늘 확정됐다. 비밀번호 관리 기업 1Password는 직원 GitHub 계정 침해를 통해 백엔드 서비스에 악성코드를 심긴 사실을 인정하고 고객 이름·이메일·계정 ID·공개키·SRP 파라미터·초대 및 복구 토큰이 빠져나갔다고 공개했다 — 종단간 암호화 설계 덕분에 금고 자체는 무사했지만, 보안 기업조차 개발자 계정 한 개로 무너질 수 있음을 증명한 사건이다. 경계 장비와 소프트웨어 조달 창구도 동시에 뚫렸다. Palo Alto Networks는 인터넷에 관리 인터페이스가 노출된 PAN-OS 장비를 노려 PHP2Shell과 'Fragnesia' 결함을 연쇄 악용하는 실제 공격을 경고했고, CISA는 Drupal 코어 재설치 유도 결함 'Fail2Install'을 KEV에 등재했으며, Elixir 공식 패키지 레지스트리 Hex.pm에서는 10년 묵은 CVSS 10.0 결함으로 프로덕션 서버 6대가 침해됐다. 국가 기관도 예외가 아니어서 미 재무부 FinCEN이 비인가 접근을 탐지하고 시스템을 예방적으로 오프라인 전환했고, 이탈리아·스위스는 자율 AI 에이전트 기반 공격에 대비하라는 공동 경보를 냈다. 국내에서는 더존비즈온 공급망 피해 우려가 53곳을 넘어선 가운데 한국투자저축은행(8만 6,433명)·배재대·순천대·한국생산성본부가 하루 만에 연쇄 유출을 공지했고, 반복적 전수점검과 처벌 중심 규제가 골든타임을 해친다는 '규제의 역설' 논쟁이 커지고 있다
국내외 주요 정보보안 이슈 요약 및 심층 분석 — 아침판

2026년 11월 26일자 목요일 아침 다이제스트. 축: '신뢰의 사슬 붕괴' — 오늘의 네 전선(보안 SaaS의 개발 파이프라인, 경계 장비와 패키지 레지스트리, 국가 금융·첩보기관, 국내 공급망 연쇄 유출)은 모두 '믿고 맡긴 고리'가 공격받은 공통 구조를 갖는다. 주차 누적 문서는 2026년 11월 4주차 다이제스트에 기록된다.

1Password가 인정한 침해 —
GitHub 계정 한 개가
백엔드를 변조했다

11-19 직원 GitHub 계정 침해 탐지 → 11-25 조사 결과 공식 발표 / 복구 인증코드 6자리→10자리 영숫자 강화
  • 1Password는 11월 19일 포착한 직원 회사 GitHub 계정 침해의 조사 결과를 25일 공개했다 — 공격자는 비공개 소스코드 저장소와 CI/CD 파이프라인에 침입한 뒤 백엔드 서비스에 악성코드를 심어 일부 고객의 이름, 이메일, 계정 ID, 로그인 타임스탬프, 공개키, SRP 파라미터, 초대·계정복구 링크 토큰을 탈취했다(BleepingComputer)
  • 설계는 지켜졌다: 종단간 제로 지식 아키텍처 덕분에 비밀번호 금고와 이를 보호하는 마스터 키·시크릿 키는 유출되지 않았고, 탈취된 복구 토큰도 단일신호로는 악용이 불가능(SSO 인증 또는 이메일 코드 병행 필요) — 대신 유출된 이메일·메타데이터를 악용한 2차 표적 피싱 위험이 실질적 위협으로 남았다
  • 1Password의 대응: 계정 복구 인증코드를 6자리 숫자에서 10자리 영숫자로 상향, 고객 알림과 함께 백엔드 변조분 제거·파이프라인 무결성 재검증 진행 — 딥다이브 1에서 개발자 인프라를 통한 공급망 공격면을 해부한다
출처BleepingComputer (1Password 공식 발표 11-25)

확정/추정 분리: 유출 항목 목록과 복구코드 강화는 회사 공식 발표 기준. '2차 피싱 위험'은 피해 자체이 아니라 후속 위협 평가다. 어제 호 축 '관리 평면이 뚫렸다'의 확장판 — 오늘은 관리 평면이 아니라 신뢰의 뿌리(소스코드·빌드)가 표적이 됐다.

경계 장비·레지스트리 연쇄 —
PAN-OS 체이닝에
Hex.pm 10.0까지

PHP2Shell+Fragnesia 실제 공격 경고 / Drupal 'Fail2Install'(CVSS 9.8) KEV 등재·11-27 패치 명령 · Hex.pm 서버 6대 침해
  • Palo Alto Networks는 인터넷에 관리 인터페이스가 노출된 PAN-OS 장비를 겨냥해 PHP2Shell 취약점과 'Fragnesia' 결함을 체이닝하는 실제 공격 캠페인을 경고했다(BleepingComputer) — 앞서 Check Point 관리 서버 22개 조직 침해(GT13)에 이어, 방화벽·VPN 관리 포트 노출이 즉각적인 내부망 붕괴로 이어지는 패턴이 굳어지고 있다
  • CISA는 Drupal 코어에서 install.php 재실행을 유도해 사이트 탈취·원격 코드 실행에 이르는 'Fail2Install'(CVE-2026-132165, CVSS 9.8)을 KEV에 등재하고 11월 27일까지 패치를 명령했다(The Hacker News) — GeoServer도 무인증 파일 읽기·우회 결함(CVE-2026-120705·CVE-2026-129243)의 실제 악용이 확인됐다
  • Elixir·Erlang 공식 패키지 레지스트리 Hex.pm은 2016년부터 코드에 존재했던 CVSS 10.0 원격 코드 실행 결함으로 프로덕션 서버 6대가 침해됐다고 밝혔다(The Hacker News) — 운영팀은 최초 보고 후 15분 만에 전 서버 패치, 전체 세션 키 교체, 사용자 2단계 인증 재설정 안내로 대응 속도를 입증했다
출처BleepingComputer · The Hacker News (Drupal / Hex.pm)

Fragnesia는 Palo Alto가 추적 중인 결함 코드로, 벤더 경고 기준이며 상세 기술 정보는 제한적이다. Hex.pm의 '15분 패치'는 대응 모범 사례인 반면, 같은 레지스트리가 10년간 치명적 결함을 방치한 사실은 조달 체인의 감사 부재를 드러낸다 — 의존성 목록 관리와 미러링이 방어 측 의무로 남는다.

Deep Dive 1

금고는 지켰지만 파이프라인이 뚫렸다 —
개발자 계정이 된
새 공급망의 급소

  • 1Password 사건의 구조: 암호학적으로는 완벽에 가까운 설계(제로 지식 금고)가 그대로 유지됐음에도, 공격자는 그 옆의 '사람과 도구'를 뚫었다 — 직원 GitHub 계정 하나 → 비공개 저장소·CI/CD 접근 → 백엔드 서비스 악성코드 주입 → 고객 메타데이터 유출 암호가 아니라 프로세스가 무너진 지점이며, SolarWinds 이후 반복돼 온 공급망 공격의 최신 변형이다
  • 같은 날 Hex.pm(CVSS 10.0)과 Drupal Fail2Install은 공격면이 '제품 자체'에서 '제품으로 오는 길'로 이동했음을 보여준다 — 빌드 인프라, 패키지 레지스트리, 설치 스크립트처럼 무인 상태로 상시 가동되는 조달 경로가 자동화 크롤링의 1순위 표적이 됐다 취약점 수명주기가 '배포 후 관리'에서 '조달 전 검증'으로 앞당겨져야 한다는 뜻이다
  • 방어 원칙: 소스코드 커밋부터 프로덕션 배포까지 전 구간에 하드웨어 토큰 기반 서명(FIDO2·sigstore류)과 다인 승인(two-person rule)을 강제하고, CI/CD 런너의 자격증명을 단기화·최소 권한화 — 1Password가 복구 코드를 10자리 영숫자로 올린 것처럼 '신뢰 지점의 entropy를 올리는' 후속 조치가 업계 표준으로 확산될 가능성이 크다
출처BleepingComputer · The Hacker News 종합 분석

국내 이관: 더존비즈온 공급망 53곳+ 사건과 오늘 1Password·Hex.pm은 같은 강의 두 사례다 — '벤더를 신뢰한다'는 말은 이제 '벤더의 빌드·조달 파이프라인을 검증할 수 있다'는 뜻으로 재정의돼야 한다. 발주처 점검 항목에 벤더의 CI/CD 서명·게이트 정책 확인을 추가할 것.

Deep Dive 2

규제의 역설 —
전수점검 서류가 잡아먹는
골든타임과 복구 실패의 반복

  • 하루 다섯 기관 유출, 배재대 '동일 해커 재침입'이라는 결과는 탐지 실패가 아니라 대응 체계의 실패다 — 침해 통보 직후 실무 인력은 차단·포렌식에 써야 할 시간을 당국의 엑셀 전수점검 양식 작성에 투입하고, CISO 개인 징벌 리스크가 과소 보고·축소 보고 유인을 만든다는 것이 금융권 실무진의 지적(보안뉴스)
  • 더존비즈온의 '계약 해지 고객사 백업 미파기' 쟁점은 같은 체계의 다른 얼굴 — 법은 위탁 데이터 파기 의무를 규정했지만, 실제 파기 이력을 검증하는 장치는 사고가 터진 뒤에야 사후 점검으로 작동한다 규제가 '사전 통제'가 아니라 '사후 서류'로 소비될 때, 방어 자원과 규제 자원은 모두 손실된다
  • 대안 프레임: 점검 중심에서 복구력(resilience) 중심으로 — ① 사고 초기 72시간은 당국 보고 서식을 최소한(발생·영향·조치 3단)으로 단순화하고 단계적 보강 ② CISO 징벌 대신 조직 단위 복구 성과 지표(탐지→차단→복구 시각) 평가 ③ 위탁 파기 이력의 기계적 검증(자동 삭제 로그)을 규제 준수 증명으로 대체 —처벌 만능주의가 반복 침해를 낳는 악순환을 끊는 관건은 '무엇을 제출하게 하는가'가 아니라 '무엇을 지키게 만드는가'다
