패치가 도착하기 전에 뚫린다 — 오늘의 뉴스는 전부 그 시간차에서 터졌다. OpenAI와 Cisco는 서비스 재시작 없이 미패치 취약점의 악용만 막는 eBPF 기반 오픈소스 방어 도구 'Shirudo'를 공개해, 기계 속도의 1-Day 공격에 대한 방어의 시계를 앞당겼다. 같은 날 보안 벤더 Radware는 인증 없이 노출된 내부 관리 API로 고객 클라우드 자격증명이 유출됐다고 밝했고, Microsoft와 노르웨이 NSM은 Azure API Management Classic 결함의 실제 악용을 경고했다. Broadcom은 제로데이 패치 며칠 만에 vCenter 디렉터리 서비스의 또 다른 CVSS 9.8 인증 우회를 포함해 23개 결함을 긴급 수정했고, GreyNoise는 17개국 22개 조직의 Check Point 관리 서버가 방화벽 무력화까지 당한 GT13 캠페인을 공개했다. 국내에서는 결제·VAN 기업 웰컴페이먼츠와 KIS정보통신의 유출이 신고됐고, 포티넷은 한국 랜섬웨어 피해가 작년의 2.4배로 급증했다고 경고했다
국내외 주요 정보보안 이슈 요약 및 심층 분석 — 아침판

2026년 11월 25일자 수요일 아침 다이제스트. 축: '패치 전야' — 패치가 배포되기까지의 시간 창이 오늘의 모든 사고(관리 평면 노출, 가상화 연타 인증 우회, 결제망 침해)에서 공격자의 진입로로 쓰였다. 부축은 방어의 속도 전환(Shirudo의 런타임 가상 패치)과 국내 결제 인프라·랜섬웨어 급증 경고. 주차 누적 문서는 2026년 11월 4주차 다이제스트에 기록된다.

Top Story 1

OpenAI·Cisco 'Shirudo' —
재시작 없이 미패치
취약점을 막는 방패

오픈소스 공개 (BleepingComputer) · eBPF 런타임 차단 + AI 규칙 생성 + 인간 승인·TPM 감사
  • OpenAI와 Cisco가 Linux 커널의 eBPF 기술을 활용해 서비스 재시작 없이 미패치 취약점의 악용을 임시 차단하는 오픈소스 런타임 방어 도구 'Shirudo'(일본어 '방패')를 공동 발표했다(BleepingComputer) — AI 에이전트가 취약점 발굴과 익스플로잇 작성을 수시간 내 자동화하면서, 테스트와 무중단 배포에 수일~수주가 걸리는 정기 패치 주기가 구조적 한계에 부딪힌 데 대한 방어 측의 대응이다
  • 동작 방식: AI 에이전트가 취약점 원인을 조사해 표적화된 차단 규칙(Shield)을 작성하고 정상 트래픽 영향 여부를 사전 검증한 뒤, 최종 프로덕션 배포는 인간 운영자의 승인 하에 커널에 즉시 적용된다 — 커널 소스 수정이나 재배포 없이 취약한 코드 경로로의 악용 행위만 정밀 차단한다
  • 신뢰 배포 체계: 암호화 서명과 Linux eBPF 검증기로 규칙 변조를 막고, TPM을 이용해 방어 규칙의 로드·제거 이력을 하드웨어 수준에서 검증 가능하게 기록 — 패치 배포 전까지의 공백을 '자율 방어 인프라'로 메우는 모델이며, 딥다이브 1에서 아키텍처를 해부한다
출처BleepingComputer (OpenAI·Cisco 공동 발표)

핵심 설계 철학은 'AI가 쓰되, 켜는 것은 사람' — 규칙 생성은 자율, 프로덕션 적용은 인간 승인(human-in-the-loop)으로 분리한 점이 자율 방어 논쟁의 절충안이다. 가상 패치(virtual patching) 개념 자체는 신규가 아니지만, AI 에이전트가 규칙을 쓰고 검증기·TPM이 무결성을 보증하는 전 과정을 오픈소스로 공개한 것이 차별점.

Top Story 2

관리 평면이 뚫렸다 —
Radware 고객 키 유출 ·
Azure APIM Classic 악용

Radware: 인증 없는 관리 API 노출로 고객 클라우드 자격증명 유출 / MS·NSM: APIM Classic 실제 악용 경고
  • 보안 기업 Radware(고객 약 1만 2,500곳)는 인증 없이 공용 인터넷에 노출된 내부 Cloud WAF 관리 API를 통해 고객 연락처와 로그 내보내기용 고객 클라우드 액세스 키(AWS S3, Azure Blob SAS 토큰, SFTP 자격증명)가 유출 가능했음을 확인하고 긴급 키 교체를 권고했다(BleepingComputer) — 11월 19일 노출을 10시간 만에 탐지·차단했고, WAF 트래픽 검사나 DDoS 방어 망은 무사했으나 이미 일부 고객사에서 낯선 IP의 AWS 버킷 접근 경보가 발생했다
  • 같은 날 Microsoft와 노르웨이 국가보안청(NSM)은 Azure API Management(APIM) Classic 티어(v2 제외)의 관리 결함이 실제 악용 중이라고 경고했다(The Hacker News) — 문서화된 보안 설정을 따르지 않은 인스턴스의 관리 기능에 무단 접근해 저장된 액세스 토큰과 시크릿을 탈취하는 공격으로, Equinor 등 에너지 기업이 영향을 받았다. MS는 11월 19일 서버 패치를 완료했다
  • 공통 교훈: 보안 솔루션과 API 게이트웨이가 보유한 '로그 내보내기·통합 관리용 자격증명'이 공격자의 최우선 표적으로 부상 — 로그 저장소 권한은 쓰기 전용으로 최소화하고 IP 조건부 액세스와 단기 토큰을 적용해야 한다
출처BleepingComputer · The Hacker News · NSM/Microsoft 공지

확정/추정 분리: Radware의 노출·차단 시각(11-19, 10시간)과 유출 가능 항목은 회사 확인 기준, '일부 고객사 AWS 버킷 접근 경보'는 피해 징후 단계로 개별 조사가 진행 중이다. APIM Classic은 v2와 달리 관리 평면이 공용 엔드포인트에 노출되는 구조적 차이가 원인이므로 Classic 인스턴스 전수 목록화가 1순위 조치다.

vCenter 또 다른 9.8
Check Point 22개 조직

  • Broadcom이 중국 연계 APT(Armory Castle)의 제로데이 악용(CVE-2026-123890)을 패치한 지 며칠 만에, VMware Directory Service(vmdir)의 또 다른 독립적 무인증 우회 결함(CVE-2026-123903, CVSS 9.8)과 임의 파일 쓰기 원격 코드 실행(CVE-2026-123904) 등 23개 취약점을 긴급 수정했다(The Hacker News) — QiAnXin·depthfirst·ThreatBook 등이 제보한 신규 결함으로, 가상화 제어 플레인이 며칠 간격으로 동일 등급 인증 우회에 연타 노출됐다
  • GreyNoise는 17개국 22개 조직(정부·금융·에너지·제조)의 Check Point 보안 관리 서버 24대가 침해된 'GT13' 캠페인을 공개했다(BleepingComputer) — SmartConsole 인증 우회(CVE-2026-16232)와 Rejetto HFS 결함(CVE-2026-61500) 릴레이로 방화벽 DB와 내부 CA 인증서를 탈취하고 보안 정책을 해제(방화벽 무력화)한 뒤 Citrix·Ivanti·NetLogon 등으로 횡적 이동을 시도했다
  • 공통 구조: 경계 장비의 '관리 평면'이 정면 표적이 됐다 — vCenter 관리망과 방화벽 관리 서버는 물리·논리적 망분리와 관리 트래픽 최소 노출이 원칙이지만, 이번 연쇄로 관리 계층 자체가 침투 경로로 굳어지고 있다
출처The Hacker News · GreyNoise / BleepingComputer

GT13에서 내부 CA 인증서 탈취는 단순 데이터 유출이 아니라 '위조 자격증명으로 내부 어디든 되는' 단계다 — 탈취 CA 인증서(서명 자격증명)의 폐기·재발급 계획이 방화벽 정책 복구보다 선행돼야 한다. CVE-2026-123903은 제로데이 확인 보고는 없으나 동일 계열(vmdir) 결함의 연타라는 점에서 패치 전 관리망 노출 차단이 급선무.

Deep Dive 1

기계 속도 공격 vs 정기 패치 —
Shirudo가 여는
2단계 복원력 모델

  • 시간 비대칭이 문제의 본질이다: AI 에이전트는 취약점 공개 후 수시간 내에 표적 익스플로잇을 만들어내지만, 기업 패치 주기는 테스트·카나리·무중단 배포를 거쳐 통상 수일~수주 — 이 '패치 전야' 창이 실질적인 침해 발생 구간이며, Shirudo는 이 구간만 잘라내는 도구다
  • 아키텍처 4요소의 의미: ① eBPF 무중단 차단 — 커널 소스 수정·재시작 없이 취약 코드 경로로의 악용 행위만 저지, 가용성 비용 0 ② AI 보조 + 인간 통제 — 규칙(Shield) 생성과 정상 트래픽 영향 검증은 AI, 프로덕션 적용 승인 사람은 운영자 ③ 암호화 서명 + eBPF 검증기 — 규칙 변조 방지 ④ TPM 감사 — 로드·제거 이력의 하드웨어 수준 무결성 기록 — 'AI가 쓴 코드를 커널에 넣는다'는 최대 반론 지점을 서명·검증기·TPM 3중 장치로 선답한 구조다
  • 장기 시사점: 방어 진영의 기본형이 '정기 패치 중심'에서 '즉각적 런타임 가상 패치(eBPF Shield) + 검증 후 코드 패치'의 2단계 자율 복원력 모델로 이동한다 — 가상 패치는 임시방편이 아니라 패치 수명주기의 앞단이 되며, 문제는 남는다: 누가·어떤 기준으로 AI 생성 규칙의 오탐(정상 업무 차단) 위험을 감수 판정하는가. 결국 Shirudo의 성패는 기술보다 승인 거버넌스 설계에 달렸다
출처BleepingComputer · OpenAI·Cisco 발표 종합 분석

국내 이관: 금융·공공의 무중단 요구 시스템(결제, 민원, 전산망)은 패치 창이 길수록 노출이 크다. eBPF 기반 가상 패치는 커널 버전 의존성이 있어 도입 전 커널 지원 범위 확인이 필요하며, 'AI 규칙 → 인간 승인' 워크플로우는 기존변경관리 절차에 통합 설계해야 한다. 어제 호 인도 경보의 '기계 속도에 사람이승인 창이 병목' 문제와 정반대 방향에서 같은 질문을 던지는 사건이다.

Deep Dive 2

'지키는 제품'이 뚫린다 —
보안 공급망 관리 평면의
자격증명 위생

  • 오늘 세 사건(Radware 관리 API, Azure APIM Classic, GT13의 Check Point 관리 서버)은 모두 같은 층을 겨눴다: 고객이 신뢰해서 내부에 넣어둔 제품의 '관리 평면' — WAF·API 게이트웨이·방화벽은 본래 트래픽 검사용이지만, 그 관리 API와 통합 자격증명은 고객 데이터 저장소(S3·Blob·SFTP)로 이어지는 통로다. 제품을 산 행위 자체가 공격면을 사는 셈이 됐다
  • 공격자 관점의 합리성: WAF를 뚫으려면 제로디이가 필요하지만, 관리 API가 인증 없이 걸려 있으면 아무 기술이 필요 없다 — Radware는 10시간 만에 차단했지만 그 사이에 로그 내보내기용 고객 SAS 토큰·SFTP 자격증명이 노출 범위였고, 일부 고객 AWS 버킷에서 낯선 접근 경보가 실제로 울렸다. GT13은 한 발 더 나가 내부 CA 인증서까지 훔쳐 '합법처럼 보이는' 위치를 확보했다
  • 방어 체크리스트 4항목: ① 관리·내부 API의 인터넷 노출 전수 조사 — 문서화되지 않은 엔드포인트가 Radware 사건의 출발점 ② 로그 내보내기 자격증명 최소 권한 — 쓰기 전용, 읽기 금지, 단기 토큰(STS/SAS 만료 단축), IP 조건부 액세스 ③ 벤더별 '관리 평면 노출' 공지 추적 체계 — APIM Classic처럼 티어별 구조 차이가 있는 제품의 전수 목록화 ④ CA·인증서 평면 감시 — 발급량 이상 탐지와 폐기(CRL/OCSP) 대응 계획 사전 수립
