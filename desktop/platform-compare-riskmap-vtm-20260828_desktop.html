Executive Summary

한눈에 보는
두 제품

RiskMap — 다온기술 (2013)
  • "국내 최초 CAASM 플랫폼" — Agent·Radar·Connector·Credential Scan 4중 수집 체계
  • RAL(Risk Acceptance Level) 기반 위험 관리, 특허 5건(4 등록 + 1 출원)
  • AI 코파일럿(자연어 질의응답) · RiskMap 1.6 (2026) · 슬로건 "Blind Spot Zero"
withVTM — 위드네트웍스 (2009)
  • "취약점을 실제 위협과 연계해 관리" — 에이전트리스 스캔, 멀티 스캐너 통합(Nessus/Qualys/OpenVAS)
  • VRS(AI 위험도 스코어링), 보안 디지털 트윈(3D) · GS인증 1등급(KTL, 2026.04)
  • withVTM V3.0 (2026) · 표어 "무엇을 먼저 보호해야 하는가"
공통점둘 다 나라장터 디지털서비스몰 등록 — N2SF·망분리 대응 자산 현행화라는 같은 시장 겨냥

요약: RiskMap은 CAASM + 4중 수집 + RAL + 특허 5건, withVTM은 VTM 철학 + 에이전트리스 + 멀티 스캐너 + VRS + GS인증 1등급. 둘 다 나라장터 등록, N2SF 대응이 공통 화두.

Deep Dive 1 · RiskMap

RiskMap:
수집의 물리량
"단 한 대도
놓치지 않겠다"

에이전트 발 심층 정확도 노선
핵심 역량
  • 4중 자산 수집: 에이전트(OS/패치/SW 직접 수집) + Radar(L2/L3·ARP·스위치 연동 비식별 자산 능동 탐지) + Connector(AWS/Azure/GCP API) + Credential Scan
  • AI 코파일럿: "신규 취약점 상위 10건" 자연어 질의 → 조회·집계·우선순위·담당자 지정·조치 가이드 (전용 모델 서버 필요)
  • Advanced: EOS 자산 관리, SSL 인증서 만료, 불법 라이선스·비인가 SW 탐지
1.6 신기능 (2026) & 특허
  • Relay Server — 지사·폐쇄망·망분리 구간 자산 중앙 통합 (N2SF 전환 대응), 백업·복구 신설, macOS 에이전트 추가
  • 특허 5건: 위험도 관리, 네트워크 기반 미식별 자산 탐지, 고유 속성 기반 변화 감지·중복 제거, DHCP/고정IP 무관 완전 자산 식별(출원)
출처riskmap.co.kr · 보안뉴스 "다온기술, RiskMap 1.6 출시" · ISEC 2026 미리보기

RiskMap 심층: 4중 수집 체계와 스위치/ARP 연동 Radar가 물리적 강점. AI 코파일럿은 LLM 기반 UX 효율. 1.6에서 Relay Server로 망분리 구간 대응, macOS 지원 추가. 특허 5건 포트폴리오.

Deep Dive 2 · withVTM

withVTM:
운영의 지능
"1000개 중
지금 할 10개"

에이전트리스 기동성 노선
핵심 역량
  • 에이전트리스 스캔: IP/MAC·OS·SW·서비스·오픈포트·연결 관계 자동 발견 — 섀도 IT 탐지, 모 대기업 도입 후 관리 자산 35% 증가(제조사 발표)
  • VRS(AI 위험도 스코어링): CVSS + 비즈니스 중요도 + 네트워크 위치 + 데이터 민감도 + TI 기반 공격 가능성 + 피해 규모 + 패치 난이도의 6차원 우선순위
  • 멀티 스캐너 통합: Nessus·Qualys·OpenVAS 결과 재해석 — 벤더 종속 없음. 다크웹 제로데이 정보 수집
V3.0 신기능 (2026)
  • 보안 디지털 트윈(3D): ISEC 2026 첫 공개 — 인프라를 3D 가상 재현, 위험 등급별 조치 유도
  • 제로트러스트 인텔리전스 허브: 자산 위험 컨텍스트를 정책 엔진에 실시간 제공, 취약 단말 동적 통제 · ITSM 네이티브(ServiceNow/Jira/BMC) + 규제 템플릿(ISMS-P·PCI-DSS·N2SF) 증적 자동 수집
출처위드네트웍스 블로그 · 보안뉴스 "withVTM V3.0 GS인증 1등급" · 지디넷 (ISEC 2026)

withVTM 심층: 에이전트리스 기동성, 6차원 VRS 스코어링, 멀티 스캐너 벤더 중립 통합. V3.0에서 3D 디지털 트윈과 제로트러스트 인텔리전스 허브 추가. GS인증 1등급, 한국주택금융공사 레퍼런스.

Compare 1

근본 차이:
에이전트 혼용
vs 에이전트리스

자산 수집 방식
  • RiskMap: 에이전트로 설치 SW·보안구성까지 정밀 수집 — 라이선스 감사·비인가 앱 차단 요구에 유리. 단, 배포 부담 존재
  • withVTM: 스캔 기반 원격 파악 — 대규모·빈번 변동 환경의 빠른 전개에 유리, 별도 구축 부담 낮음
위험 관리: RAL vs VRS
  • RAL(RiskMap): 조직의 "수용 가능 위험 수준" 정책 기준으로 조치 대상 자동 선별 — 거버넌스형, 정책 명확성
  • VRS(withVTM): 다차원 가중치 AI 스코어링 — 분석형, 위협 인텔리전스 반영 폭이 넓음
  • 핵심 질문: 우선순위 기준을 직접 정의할 의지(RAL) vs 벤더 모델에 위임(VRS)
평가"CVSS 만능주의" 비판에서 출발한 같은 문제의식, 서로 다른 해법 — 정책 중심 vs 데이터 중심

비교 1: 수집은 에이전트 심층 정확도(RiskMap) vs 에이전트리스 기동성(withVTM). 위험관리는 RAL 거버넌스형 vs VRS 분석형. 조직의 우선순위 정의 의지가 선택 기준.

Compare 2

AI 활용축과
생태계 통합

AI 전략 — 정면 충돌보다 차별화
  • RiskMap: "쓰기 편한 보안 도구" — LLM 코파일럿 대화형 UX·운영 효율 (대시보드 빌더 병행)
  • withVTM: "판단해주는 두뇌 + 보이는 인프라" — VRS 스코어링 + 3D 디지털 트윈 예측·시뮬레이션
생태계 — 공급사 DNA vs 서비스 DNA
  • 다온기술: Trellix·CrowdStrike·Logpresso 총판 병행 — 솔루션 공급·구축 역량과 결합, EPP/EDR API 수집
  • 위드네트웍스: Radware·Fortinet 파트너 + MSSP 자체 관제 — 운영 리소스가 부족한 조직은 withVTM+MSSP 조합에 매력
평가향후 차별화 경쟁은 "AI로 무엇을 대신해주는가"의 구체성으로 판가름

비교 2: AI는 RiskMap LLM UX vs withVTM 분석 모델·시뮬레이션. 생태계는 모회사 DNA(공급사 vs 서비스)가 반영 — MSSP 결합 여부가 운영 열위 조직의 관전 포인트.

Use Cases

시나리오별
추천

RiskMap이 적합한 경우
  • 설치형 에이전트 정밀 인벤토리 필요 (SW 라이선스 감사, 비인가 앱 차단)
  • "수용 가능 위험 수준"을 정책·감사에 활용하려는 공공·금융 기관
  • DHCP·비인가 기기 탐지가 중요한 대규모 내망, macOS 포함 멀티 OS 관제
withVTM이 적합한 경우
  • 에이전트 불허 정책·빈번한 자산 변동 — 즉시 가시성 확보 환경
  • Nessus/Qualys 기존 자산의 통합 재해석, ISMS-P·PCI-DSS 증적 자동화·ITSM 워크플로우가 급한 기업
  • 제로트러스트에 위험 컨텍스트 공급, 3D 트윈 경영진 보고, MSSP 결합 중견기업
공통 권고POC로 '우리 환경의 미탐지 자산 수'와 '조치 워크플로우 적합도' 직접 비교가 가장 정확

시나리오 추천: 정밀 원장·거버넌스 중심이면 RiskMap, 기동성·운영 자동화·관제 결합이면 withVTM. 최종 선택 전 POC로 미탐지 자산 수와 워크플로우 적합도 검증 권고.

Conclusion

우열이 아닌
역할 분담

① 카테고리 경계의 소멸
Tenable·Qualys처럼 국내도 '자산 식별 + 취약점 + 위험 기반 조치 추적' 단일 플랫폼으로 수렴 — 두 제품은 같은 구매 의사결정 테이블에 올라감
② N2SF가 공통 경쟁 축
망분리 환경의 '자산 목록과 실제 네트워크 불일치'가 국내 1번 페인포인트 — Relay Server(RiskMap) vs CTEM 체계(withVTM)
③ 최종 선택의 4가지 질문
(1) 에이전트 허용 여부 (2) 기존 스캐너 자산 (3) 규제 부담 유형 (4) 운영 인력 규모 — 원장 완전성 최우선이면 RiskMap, 발견-판단-조치-감사 자동화 최우선이면 withVTM
결론"자산에서 시작하는 위험 기반 보안"이라는 같은 철학, 서로 다른 엔지니어링 전통

결론: 카테고리 수렴, N2SF 공통 축, AI 차별화 경쟁. 최종 선택은 에이전트 허용·기존 스캐너·규제 부담·운영 인력 4가지 질문으로 좁혀진다.
