AI가 리눅스 커널에서
Root 취약점 948개를 찾다
— 오픈AI 연구 특집

2026. 11. 05 (THU)
$180만 = 커널 한 개
LPE 하나당 $1,279 — 포상금의 16~55배 남는 장사
석 달 새 5.7배
GPT-5.6 Sol 166개 → 신모델 948개
인간도 몰랐던 기법 10종
외부 전문가가 "처음 본다"고 한 공격법
오픈AI가 11월 4일 공개한 연구 'A thousand fewer paths to root' — 아직 미공개 차기 사이버 모델로 리눅스 커널 대상 에이전트 파이프라인(정찰→분석→재현→공격 코드→패치)을 10월 중순 가동, 후보 2,308개 중 1,724개를 동적으로 재현하고 그중 비특권 로컬 계정이 root를 탈취하는 LPE 취약점 948개에 대해 작동하는 공격 코드와 개별 패치를 생성했다. 총 API 비용 $1,213,430(약 17억 원), LPE 하나당 평균 $1,279 — Pwn2Own·TyphoonPWN 상금 기준 환산 시 16~55배의 '수익'. 강화된 Google kernelCTF 환경에서도 정보유출 PoC 25개·LPE 21개를 확보했는데 이는 올해 kernelCTF 인정 제로데이 전체(26개)에 육박하는 규모. 표본 분석에서 외부 전문가가 처음 본 신규 익스플로테이션 기법 10종 발견(메모리 캐시 배치 2, 페이지 배치 2, 무실행 데이터 변형 5, 타입 혼동 1 — 안전상 세부 비공개). 사람 연구자는 최종 검토·신고만 담당. 오픈AI의 결론: "당분간 최신 패치 없는 OS의 일반 계정은, 자원 있는 공격자에게 root와 사실상 같다"
단일 사안 심층 특집

2026년 11월 5일자 특집 다이제스트. Threads(@choi.openai)에서 확산된 '오픈AI가 리눅스 취약점 948개 발견' 타래를 오픈AI 원문(openai.com/index/a-thousand-fewer-paths-to-root, 11.4)과 전수 대조했다. 타래의 핵심 수치(2,308/1,724/948/$1,213,430/$359·$3,922/166개→948개/기법 10종/61-43-299)는 모두 원문과 일치함이 확인됐다. Pwn2Own·TyphoonPWN 상금 비교는 타래 저자의 계산(오픈AI "포상금 기준으로 남는 장사" 표현에 근거). 이 덱은 사실 검증 위에 '보안 산업에 무엇이 바뀌는가'를 덧씌운다.

무엇이 자동화됐나 —
정찰부터 패치까지 다섯 단계

사람은 마지막 검토·신고만 · 통제된 연구 환경에서 수행 — 악용 사례 아님
파이프라인 실측
  • ①Scout(정찰): 커널 폴더·파일을 훑어 비특권 사용자가 건드릴 수 있는 보안 관련 코드 5,034곳(약 280만 줄, 커널 전체의 7%) 선별 — 비용 $3,426 / ②Analyst(분석): 12시간 만에 중복 제거 후보 2,308개 — $316,549 / ③재현: 후보마다 테스트 코드를 직접 짜서 KASAN 켠 격리 VM에서 반복 실행, 30시간에 1,724개(74.7%) 실버그 확인 — 미재현 중 '모델 분석 오류'는 고작 3.1%, 68.9%는 애초 특권 필요
  • ④위험도 선별·공격 개발: 1,724개를 정보유출 313·권한상승 1,238로 분할, SMEP/SMAP/KASLR 켠 일반 배포판급 VM에서 시험 → 유출 PoC 291개 + 작동하는 LPE 공격 코드 1,169개 / ⑤변형 분석→패치: 같은 원인 묶어 서로 다른 패치 948개(=고유 LPE 수) — 성공 공격 코드 1건 평균 $359, 실패 69건 건당 $3,922(실패가 10배 비쌈)
  • 역사: 6월 22일 Daybreak 확장+Patch the Planet(오픈소스 보안 지원)에서 GPT-5.5 Cyber로 커널 LPE 공격 코드 24개 신고 → 7월 말 GPT-5.6 Sol로 파이프라인 프로토타입, LPE 166개/$513,690 → 10월 중순 미공개 신모델로 948개/$1,213,430 — 같은 최신 커널 대상, 그 사이 커널은 계속 보강됐는데 성과는 5.7배
출처OpenAI — A thousand fewer paths to root(11.4) 원문 전 수치 대조

오탐통계 주의: '재현 실패의 68.9%가 특권 필요 케이스'는 모델이 버그를 잘못 본 것이 아니라 위험도 판단의 차이 — 실제 오탐(존재하지 않는 버그)은 3.1%. 이 숫자가 파이프라인 성숙도의 핵심 지표다.

News 2

경제학이 무너졌다 —
커널 제로데이 1개의 원가

LPE당 $1,279 vs 커널 대회 상금 $2만~7만 — kernelCTF 올해 인정 제로데이 26개에 21개 근접
비용과 가치의 역전
  • 엔드투엔드 $1,213,430로 고유 LPE 948개 — 건당 $1,279(약 180만 원) : 타래 저자는 Pwn2Own($2만)·TyphoonPWN($7만)의 커널 LPE 상금과 대조해 948개 기준 $1,890만~$6,630만(16~55배) 가치를 산출했다. 오픈AI 원문도 "공개 포상금 기준으로 이미 채산성이 있었다"고 명시 — 상금 액수 자체는 타래 저자의 계산
  • 가장 단단한 표적에서도 통했다 — Google kernelCTF(공격 표면 축소·완화 강화 커널) 환경 실행에서 정보유출 PoC 25개 + LPE 21개 확보, 올해 kernelCTF가 인정한 제로데이 LPE 총량은 26개 : 한 번의 파이프라인이 1년치 대회 실적을 거의 갈아먹은 셈(단, SLAB_VIRTUAL 완화는 호환 문제로 제외하고 돌린 실험임을 원문이 병기)
  • 공급 측 과잉의 증거 — 스캔 완료 후 10일 안에 찾아낸 LPE 중 61개는 이미 다른 기여자 패치가 반영됨, 43개는 스테이징 패치 대기, 299개는 공개 신고·논의 중 : 여러 AI 연구팀이 같은 커널을 동시에 훑고 있다. '숨은 제로데이'의 시대 종료 — 발견 독점이 사라지면 값어치는 선점 속도와 패치 품질로 이동한다
출처OpenAI 원문(kernelCTF·61/43/299 단락) · 타래 저자 상금 환산(별도 표기)

블랙마켓과 합법 포상금은 별개지만, '발굴 원가가 대회 상금의 1/16~1/55'라는 비율은 공격 경제학의 중력 변화를 보여준다. 동시에 방어측에도 같은 원가 곡선: 취약점 발굴 기반 방어가 대중화된다.

News 3

기법 10종과 패치의 문제 —
모델이 '발명'하기 시작했다

외부 커널 전문가 진품 "처음 보는 기법" · AI 최초 패치는 길이 과잉·변형 누락 — 반복으로 품질 향상
두 개의 경계선
  • 에이전트 공격 코드 166개 표본 분석에서 미지의 리눅스 익스플로테이션 기법 10종: 커널 메모리 캐시에 원하는 객체를 미리 깔아두는 신방법 2, 성공률을 높이는 메모리 페이지 배치 2, 코드 실행 없이 데이터만 변형해 권한 획득 5, 타입 혼동 1 — 외부 전문가 블라인드 검토에서도 "처음 본다"였고 오픈AI는 안전상 세부 비공개. 모델이 알려진 패턴의 재조합을 넘어 기법을 발명하는 단계에 들어섰다는 증거다
  • 패치 품질은 초기 단계: 최초 생성 패치는 필요 이상 길거나 같은 결함 변형을 놓침 — 정적 검사·인접 코드 관례 준수·변형 분석이라는 커널 커뮤니티 방식을 지시·반복으로 학습시켜 끌어올렸고, 사람 전문가 패치의 결함을 AI가 잡아낸 사례도 있다 : 다만 최종 병합은 여전히 사람 멘테이너 검토를 통과해야 하는 구조
  • 동시 발견의 강화: 10월 PHP 결함에서 서로 다른 팀이 서로 다른 모델로 3주 내 같은 취약점 도달(7·8월 신고 교차) — 커널에서도 61개가 이미 남의 패치로 막혀 있었다 : '누가 먼저 찾았나'의 경쟁이 무의미해지는 속도로 수렴 중. 코드가 존재하는 한 모델 세대 교체 때마다 다시 발견된다
출처OpenAI 원문(신규 기법·패치 품질 단락) · PHP 동시 발견 사례는 타래 인용(별건)

'무실행 데이터 변형 5종'은 특히 주의 — 기존 탐지 모델이 '코드 실행'에 최적화되어 있다면 이 기법들은 사각지대다. EDR·커널 모니터링 벤더에 전달해야 할 관측 포인트.

Deep Dive 1

'948'가 보안 산업에
의미하는 것

해석 프레임
  • 취약점의 희소성이 붕괴한다 — 커널 같은 최난도 코드에서도 건당 $1,279에 LPE가 나오는 시대라면, '미발견 제로데이'는 자산이 아니라 재고다 : 모델 세대가 바뀔 때마다 모든 기반 소프트웨어가 다시 훑힌다(오픈AI의 공식 권고). 벤더는 "우리에겐 보고 안 온 0day"라는 방어를 영원히 할 수 없다
  • 보안 팀의 병목 이동이 현실화 — 이번 주 내내 반복되는 패턴: 발견 비용 ↓↓, 검증·우선순위·패치 배포 원가 그대로 : 오픈AI 스스로 재현 단계부터 자동화한 이유가 그것이고(8월 타래 예측의 실증), 노스웨스턴 연구(AI 패치 32.7%가 증상 차단)가 말하듯 '고친 척' 검수도 사람이 한다. 산업의 다음 제품은 '발견'이 아니라 '종결(closure)'다
  • 오픈AI의 마지막 문장이 이 연구의 요지 — "당분간 최신 패치를 안 한 OS의 일반 계정은 자원 있는 공격자에게 root와 사실상 같다" + 격리(샌드박스·Firecracker·gVisor) 겹겹이 권고 : AI 에이전트를 루트가 아닌 계정으로 돌려도, 커널 업데이트가 밀리면 그 격리는 무의미해진다. 패치 슬래그(slack)가 곧 침해 확률인 시대의 공식 선언
출처OpenAI 원문 결론부 · 타래 저자 과거 관찰(병목 이동·N-hour) 종합

'승부가 누가 많이 찾느냐에서 누가 빨리 고치고 덜 깨지게 짓느냐로 옮겨간다'는 타래 전망에 동의한다. 알트만의 "라우터·OS부터 다시 짜는 회사가 나온다"와 같은 계열의 주장이며, 형식 검증·기능 축소(saturation 제거) 권고가 원문에 포함되어 있다.

Deep Dive 2

이번 주 전체 그림 —
AI는 공격과 방어의 같은 연료를 태운다

주간 맥락 연결
  • 같은 한 주: 오버워치는 베이퍼팬더가 딥시크+ARTEX로 14개국 동시 침투(계획 에이전트 14억 토큰)한 것을 폭로했고, 오픈AI는 방어측 에이전트가 커널에서 LPE 948개를 찾아내는 영상을 공개했다 — 공격과 방어가 동일한 토큰 경제 위에 선다. 차이는 통제(오픈AI는 격리 환경·조정 공개·비공개 세부의 3중 안전장치)이며, 이것이 '무기'와 '연구'를 가르는 기준선이다
  • 공격측에도 발견 원가 곡선이 적용되면 — 방어 패치 분석→익스플로트 생성의 'N-hour'(패치 공개 후 워킹 익스플로잇까지 1시간대)과 결합해, 공방 모두 '발견'이 아니라 '배포 속도'에서 승부가 난다 : 오늘 아침판의 APT 결함(CVE-2026-109518)이 그 실례 — 결함 공개부터 전 세계 패치 경쟁이 이미 시작됐다
  • 한국 조직에의 함의: 리눅스 커널 기반(서버·클라우드·안드로이드)이면 예외 없고, 특히 멀티테넌트·컨테이너 호스팅은 '비특권 로컬 계정'이 곧 고객 계정 : 커널 패치 지연 용인 관행, 컨테이너 inside 사용자 권한 설계, AI 에이전트 실행 계층의 root 회피가 이번 주 안에 점검해야 할 3종 세트다
출처OpenAI 연구 · 오버워치·GTIG 주간 보고서 종합 독해

'AI 안보 딜레마'의 균형표: 방어 AI가 찾은 취약점의 개 공격 AI가 쓸 수 있는 숫자와 같다. 다만 발견→신고→패치→배포의 제도적 파이프라인이 존재하는 쪽(방어)이 구조적으로 유리하며, 그 유리함은 '배포 속도'를 지키는 한에서만 유효하다.
