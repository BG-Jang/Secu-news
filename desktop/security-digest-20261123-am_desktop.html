한전 152만 248건 연쇄 유출
한전ON·전자조달(SRM) — 주민번호+카드번호 결합 유출, 한 달 만의 재참사
OpenRouter, 'ZDR' 허상 드러나다
카나리 200만 건 추적 — 침해 방치 호스팅 3곳 퇴출, 125개 엔드포인트 자격 박탈
클라우드 관리평판·엔진 연쇄 피격
Rackspace Spot Kubernetes 시크릿 열람 / MS Entra Connect Health API 실제 악용
새 한 주의 시작이 무겁다. 한국전력공사가 고객 플랫폼 '한전ON'과 전자조달시스템(SRM)에서 주민등록번호·계좌번호·카드번호를 포함해 총 152만 248건이 유출됐다고 공식 발표했다 — 지난달 임직원 3만 5천 명 유출에 이은 한 달 만의 재참사다. AI 전선에서는 Dragos의 카나리 토큰 200만 건 추적이 '데이터 미보관(Zero Data Retention)' 약속의 민낯을 드러냈다: OpenRouter 연동 호스팅 업체 3곳이 수개월간 침해당한 채 고객 프롬프트와 AWS 키를 빼앗기고 있었고, ZDR 플래그조차 저가 리셀러로 몰래 우회됐다. 클라우드에서는 Rackspace Spot의 Kubernetes 시크릿 열람과 마이크로소프트 Entra Connect Health API의 실제 악용이 같은 날 확인됐고, Ghostscript 샌드박스 탈출(CVE-2026-125396)은 평범한 파일 업로드 하나를 서버 명령 실행으로 바꾼다. 국내에서는 CJ대한통운 챗봇과 블랙다이아몬드 외주 ERP가 새로운 접점 공격면임을 알렸다
국내외 주요 정보보안 이슈 요약 및 심층 분석 — 아침판

2026년 11월 23일자 월요일 아침 다이제스트. 축: '한전의 두 번째 문' — 같은 기관이 한 달 사이 두 번, 이번엔 대민·조달 두 개 시스템에서 동시에 뚫렸다. 부축은 신뢰의 하청(OpenRouter ZDR)과 관리평판(Rackspace·Entra), 그리고 렌더러라는 그림자 공격면(Ghostscript). 주차 누적 문서는 2026년 11월 4주차 다이제스트에 기록된다.

Top Story 1

한전 152만 248건 유출 —
주민번호·카드번호가
함께 빠져나갔다

한전ON 65만 487명 + 전자조달(SRM) 86만 9,761명 — 10월 임직원 유출 후 한 달 만의 재참사, 사장 명의 대국민 사과
  • 한국전력공사, 11월 22일 공식 발표: 11월 20일 외부 불법 접속 시도를 탐지해 조사한 결과 고객 플랫폼 '한전ON'과 전자조달시스템(SRM)에서 총 152만 248건의 개인정보가 유출 — 김동철 사장 명의 대국민 사과문이 게시됐다(보안뉴스)
  • 유출 항목의 무게가 다르다: 한전ON에서는 고객번호·성명·주민(외국인등록)번호·주소·은행명·계좌번호·카드사·카드번호·요금정보 등 12개 항목, 조달망에서는 기업 대표자 42만 6,827명의 주민번호·이메일과 한전·협력사 직원 44만 2,934명의 사번·연락처가 노출됐다 — 식별자와 금융정보가 결합된 형태라 명의도용·금융 피싱 위험이 최상위다
  • 반복되는 실패라는 점이 본질: 불과 한 달 전 10월에도 임직원 2만 4,769명(국감에서 안면인증 408명, CCTV 1만 4,957대 계정 포함 총 3만 5,528명으로 확대 확인) 노출 사고를 겪었다 — 한전은 "고객 편의·접근성을 높이기 위한 개방형 디지털 서비스 일부 기능이 표적이 됐다"고 밝혔다. 대민 기능 확장 속도에 인증·API 접근 통제와 고유식별번호 분리 보관이 따라가지 못한 구조적 문제다
출처보안뉴스 · 한전 공식 발표 (11-22)

확정/진행 중 분리: 유출 규모(152만 248건)와 항목 목록은 한전 공식 발표 기준 확정. 침입 경로·악용된 구체 기능은 조사 중으로 미공개 — '개방형 디지털 서비스 일부 기능'이라는 기관 표현 이상으로 단정하지 않는다. 후속: 방통위·개인정보위 조사, 범정부 2차 피해 방지 조치(명의도용 차단 서비스 안내 등)를 이번 주 MON 항목으로 추적.

Top Story 2

OpenRouter 퇴출 사태 —
'Zero Data Retention'의
허상을 낚아올린 카나리

Dragos, 카나리 프롬프트 200만 건 추적 — 침해 인지조차 못 한 호스팅 3곳 퇴출, ZDR 자격 125개 엔드포인트 박탈
  • Dragos 연구진이 7월부터 11월까지 카나리 토큰(고유 웹 링크·AWS 테스트 키)을 심은 프롬프트 200만 건을 AI 게이트웨이·추론 업체에 전송해 추적 — OpenRouter와 연동된 호스팅 제공업체 3곳이 수개월간 내부 침해를 당한 채 고객 프롬프트와 AWS 키를 도난당하고 있었고, 스스로 침해 사실조차 모르고 있었다(The Hacker News)
  • 탈취 지점이 예사롭지 않다: 모델에 거절된 요청까지 통째로 빠져나갔다 — 공격자가 트래픽 최전단에서 요청 전체를 복제했다는 뜻이다. 훔친 AWS 키는 11월 1일 ARTEX AI 도구로 생존 검증까지 됐다(Phala·Together AI 등은 별도 침해 공지 발표)
  • ZDR 플래그는 휴지조각이 됐다: 데이터 미보관 설정 프롬프트조차 제3자 저가 리셀러 마켓플레이스로 은밀히 포워딩 — 한 중국 AI 연구소는 모델 요청 링크의 절반 이상(ZDR 요청의 약 3분의 2 포함)을 스크래핑해 Git 저장소 복제를 시도하고 사내 메신저(Feishu)에서 열람한 정황까지 잡혔다. OpenRouter는 업체 3곳 퇴출과 125개 엔드포인트 ZDR 자격 박탈로 대응했지만, AI 추론 공급망 신뢰 위기 자체는 남았다
출처The Hacker News · Dragos 연구 (7-11월 추적)

실무 함의: 프라이버시 플래그는 계약 문구일 뿐 기술적 보장이 아니다. 기업은 AI 프롬프트에 API 키·기밀 코드를 실어 보내는 관행 자체를 금지하고, 게이트웨이 경유 시 민감 데이터 마스킹, 고감도 워크로드는 1차 벤더 직계약 또는 자체 호스팅으로 분리해야 한다. 카나리 토큰은 우리 조직 프롬프트의 실제 종착지를 확인하는 유일한 검증 수단이라는 점도 기억할 것.

Top Story 3

관리평판이 뚫렸다 —
Rackspace Spot 시크릿 열람,
MS Entra API 실제 악용

작업 부하가 아니라 그 위를 관리하는 층이 표적 — 고객은 DB 비밀번호·API 키·리프레시 토큰 전량 교체가 필수
  • Rackspace(11-21 공지): 11월 17일 공격자가 유출 고객 자격증명으로 Rackspace Spot에 로그인, 고객 Kubernetes 클러스터에 무단 파드(접두사 i1·glm-·probe)를 생성하고 DB 비밀번호·API 키가 담긴 Kubernetes Secrets와 Spot 토큰을 열람 — Rackspace와 공동 개발사 Platform9은 전체 정화를 위해 관리 콘솔 접속을 전면 차단했다가 21일 복구했다(BleepingComputer)
  • 마이크로소프트도 같은 날 인정: 온프레미스 AD 동기화 모니터링용 Entra Connect Health API에 7월 23일 도입된 취약점이 11월 9일 발견 전까지 실제 악용 — 다수 기업·MSP 테넌트의 관리자 이메일, 테넌트 ID, 초기 도메인, 동기화 상태, 만료 인증서 등 메타데이터가 무단 조회됐다(BleepingComputer)
  • 비밀번호·토큰 자체는 미유출이지만 피해 시나리오는 명확하다: 노출된 관리자 이메일을 노린 고도화 스피어피싱과 테넌트 지형 파악(초기 도메인·동기화 상태)은 침입 전 단계의 연료 — MSP처럼 다수 고객을 대리 관리하는 구조에서는 한 개의 관리평판 침해가 고객사 전체로 증폭된다
출처BleepingComputer · Rackspace 공지 · Microsoft 통지 (11-20~21)

대응 순서: ① Rackspace Spot 고객은 클러스터 내 모든 Secret·DB 비밀번호·API 키·리프레시 토큰 rotate, 무단 파드 생성 이력 감사 ② Entra Connect Health 고객은 관리자 메일 대상 피싱 경보 공지, 인증서 만료 정보 노출분 점검 ③ 관리 콘솔(IP 허용·하드웨어 MFA·조건부 접근)을 작업 부하와 다른 사령탑으로 취급하는 체계 재확인. '관리평판'과 '작업평판'의 분리 통제가 이번 두 사건의 공통 교훈이다.

Top Story 4

Ghostscript 샌드박스 탈출 —
업로드 한 번이
서버 명령이 된다

CVE-2026-125396 (CVSS 8.5) 폰트 로딩 UAF — ImageMagick·Pillow 경유 Roundcube·WordPress 등 10여 개 앱 실증
  • pwn.ai가 Ghostscript 10.08.0(9월 패치) 이전 버전의 폰트 로딩 중 use-after-free 결함(CVE-2026-125396, CVSS 8.5)으로 -dSAFER 샌드박스를 뚫는 RCE를 시연 — 앱이 Ghostscript를 직접 호출하지 않아도 ImageMagick·Pillow 등 백엔드 렌더러가 PNG·JPG·PDF 썸네일 생성 과정에서 내부적으로 호출한다. Roundcube 웹메일·WordPress 플러그인 등 10여 개 앱에서 평범한 파일 업로드만으로 서버 명령 실행이 성립했다(The Hacker News)
  • 패치 공백이 공격 창이다: Debian 12·Amazon Linux·SUSE 등 다수 배포판과 컨테이너 이미지의 업데이트가 지연 — 의존성 트리에 갇혀 버전 올림을 못 하는 애플리케이션이 그대로 무방비 노출된다. 10.08.0 이상 업그레이드와 AppArmor 격리가 시급하다
  • 국내 접점도 동시에 울렸다: CJ대한통운은 11월 16일경 배송 조회 '오네(O-NE)' 챗봇 서버에 대한 비정상 자동화 대량 접근(인수인 이름·동 단위 주소 조회)을 포착해 WAF 차단 강화와 조사에 착수(데일리시큐), 블랙다이아몬드 코리아는 주문·배송용 외주 통합 ERP 서버의 비정상 접근 통보를 받고 연동을 차단했다(보안뉴스) — 챗봇 API 열거 공격과 외주 물류 접점이 새 표적 지형이다
출처The Hacker News · pwn.ai 시연 · 데일리시큐 · 보안뉴스

공격면 관점: 렌더러는 '보이지 않는 서브프로세스'다 — 업로드 파일 검증(magic bytes만으론 부족), 썸네일 생성을 별도 컨테이너·샌드박스로 격리, Ghostscript 미설치 이미지 사용 같은 공급 단계 통제가 재발 방지에 직결된다. CJ대한통운 건은 유출 확정 발표가 아니라 '비정상 접근 포착·조사 중' 단계 — 피해 규모가 확정되기 전까지 단정 표기 금지.

Deep Dive 1

개방형 공공서비스의 청구서 —
편리함의 속도와
보안의 부채

  • 한전 사고의 방정식: '편리함'은 인증 경계를 인터넷 쪽으로 옮기는 작업이다 — 한전ON의 요금 조회·납부, SRM의 조달 참여 기능은 본래 내부망 신뢰권에 있던 데이터를 로그인 한 번이면 닿는 곳에 배치했다. 기관이 "개방형 디지털 서비스 일부 기능이 표적이 됐다"고 말할 때, 그 말은 곧 방어 책임이 인터넷 노출면으로 이동했다는 자인이다
  • 데이터 모델이 사고 규모를 결정한다: 주민번호+계좌번호+카드번호가 한 레코드에 공존하면, 뚫린 순간 2차 피해(명의도용·금융 사기)의 완결 세트가 넘어간다 — 고유식별번호는 조회 전용으로 분리 보관하고 서비스 DB에는 토큰화된 식별자만 두는 설계, 조달망 대표자 주민번호처럼 '왜 이 테이블에 필요한가'를 되묻는 최소 수집 원칙이 부채 상환의 첫 항목이다
  • 한 달 만의 재발은 사후 조치의 실패다: 10월 임직원 유출 후 특단의 통제 강화가 있었다면 11월 연쇄 유출은 막았어야 한다 — 사고 후 점검이 '권고 이행 확인'에서 끝나고 아키텍처 개편으로 이어지지 않는 공공기관 관행, 그리고 반복 기관에 대한 제재·평가 체계의 실효성이 이번 주 국정감사 이후 최대 쟁점이 된다
출처보안뉴스 · 한전 발표 종합 분석

국가·공공기관 실무 이관: ① 대민 전환(웹/모바일) 신규 기능의 보안성 검토를 오픈 전 게이트로 강제(현재는 사후 점검 중심) ② 고유식별번호 결합 보관 시스템 전수 조사·분리 일정 수립 ③ 협력사·조달 참여자 데이터는 '대외 제공 가능한 성격'으로 분류해 별도 격리. 개인 실무: 한전 고객이라면 카드 즉시 재발급·명의도용 차단 서비스(무료) 등록, 조달 참여 기업은 대표자 명의 금융계좌 동결 옵션 검토.

Deep Dive 2

신뢰의 하청 —
AI 추론 공급망에서
'플래그'는 계약일 뿐이다

  • OpenRouter 모델의 경제학이 사고를 예약했다: 게이트웨이는 최저가 라우팅을 팔고, 저가 리셀러는 로깅·재라우팅으로 마진을 만든다 — Dragos가 적발한 ZDR 우회(저가 마켓플레이스 포워딩, 중국 연구소의 요청 스크래핑)은 예외가 아니라 이 가격 구조의 필연적 탈루다. 구매자는 1차 벤더와 계약했지만 프롬프트의 실제 종착지는 공급망 최하단 리셀러였다
  • '거절된 요청'까지 훔쳐간 위치에서 교훈을 읽어야 한다: 침해는 모델이 아니라 모델 앞의 프록시·게이트웨이 계층에서 일어났다 — 트래픽 최전단 복제는 TLS 종단점과 로그 파이프라인을 가진 곳이면 가능하다. 벤더의 보안 성숙도 평가가 모델 성능 비교표보다 선행돼야 하는 이유다
  • 방어는 세 겹으로: ① 내보내기 통제 — 프롬프트에 API 키·기밀 코드를 넣지 못하게 하는 DLP와 코드 마스킹(키가 들어가면 유출면이 데이터에서 자격증명으로 격상된다) ② 라우팅 투명성 — 카나리 토큰으로 우리 트래픽의 실제 종착지 정기 검증 ③ 중대 워크로드 분리 — 고감도 추론은 1차 벤더 직계약 또는 자체 호스팅으로 공급망 밖으로

거버넌스 관점: ZDR은 '기술적 상태'가 아니라 '벤더의 선언'이다. 조달·계약 심사 시 프롬프트 보관 정책뿐 아니라 하위 재처리자(sub-processor) 목록과 감사권을 요구해야 하고, AI 게이트웨이 이용 규정에 기밀 데이터 반입 금지와 위반 시 계약 조항을 명시할 것. 자사 11-20 진트 특집(AI 코딩 에이전트 신뢰)과 같은 축 — 신뢰할 수 있는 것은 모델이 아니라 검증 가능한 경로뿐이다.
