CVE-2026-119618 심층 특집

2026년 11월 13일자 스페셜 덱. 축: 'AI가 먼저 보고, 인간이 뒤따라 확인한' 초유의 크래시 코스 — 그리고 벤더 점수(9.8)·자체 평가(Important)·NVD 미평점이 한 CVE에서 세 갈래로 갈라진 이례적 사례. 모든 수치는 Apache 공식 어드바이저·Red Hat 평가·Wiz/watchTowr 분석·THN·BC 보도 기준이며 NVD는 11-13 현재 Awaiting Analysis 상태다.

Incident Overview

결함 하나, 조건 셋 —
무엇이 얼마나 뚫리는가

CWE: 부적절한 동기화의 공유 자원 동시 실행 · assign_headers() · 인증 불필요
공식 확인 사항 (Apache 어드바이저 11.11)
  • mod_http2의 assign_headers()에서 동시 실행되는 스레드들이 공유 자원을 부적절하게 동기화해 힙 메모리가 손상되고, 최종적으로 원격 코드 실행(RCE)으로 이어질 수 있다 — Apache가 명시한 취약 버전은 HTTP Server 2.4.55~2.4.70, GitHub 독립 릴리스 mod_h2는 2.0.8~2.0.42
  • 공격 조건은 두 개뿐: 서버에 도달할 수 있는 네트워크 위치 + HTTP/2 활성화(Protocols 지시자의 h2/h2c) — 인증은 필요 없고, 성공 시 웹 서버 프로세스 권한으로 코드 실행, 서버 프로세스 전체 장악 가능하다(Red Hat 평가) — Protocols는 서버 전역과 가상 호스트 각각 설정되므로 양쪽 모두 점검 대상
  • 패치: 2.4.71(11.11 릴리스, 수정 커밋 824beab)에 critical 1건+important(mod_md NULL 역참조 CVE-2026-106023)+low(mod_vhost_alias 스택 1바이트 overwrite CVE-2026-109163) 동시 포함 — 독립 mod_h2 프로젝트는 6월 9일 리포지토리가 아카이브(읽기 전용)돼 고정 릴리스가 존재하지 않는다
출처Apache HTTP Server 보안 어드바이저 · BleepingComputer

임계 포인트는 버전 범위의 '하한 2.4.55'다 — 그 이전(≤2.4.54)은 취약 코드 도입 전이라 안전하고, 2.4.67처럼 작년 HTTP/2 결함(CVE-2026-23918)을 갱신한 서버는 오히려 이번 범위 안에 있다. '최신으로 유지'가 이번엔 통하지 않는 구간이다. mod_h2 아카이브 상태는 독립 빌드 사용자에게 비상 —upstream 패치가 없으므로 Protocols 강등이 유일한 길이다.

주목할 선례: AI 스캐너가 발견한 취약점에 벤더가 고유 ID를 부여하고 인간 연구자와 공동 크레딧한 사례로 기록될 만하다(패턴 자체는 지난 11.5 openai-kernel-948 특집에서 확인한 흐름의 연속). 실무 함의는 '발견 속도' 쪽 — AI 스캐너들이 오픈소스 핵심 코드를 상시 훑는 시대에, 제로데이 수명 주기는 더 짧아진다. 패치 배포 후 악용 개발까지 남은 시간은 몇 시간 단위가 된다.

Deep Dive 1

경쟁 조건은 왜 헤더에서 터지는가
— assign_headers() 해부

메커니즘 분석 (Apache CWE 분류·Wiz 분석 종합)
  • HTTP/2의 본질은 다중화다 — 하나의 커넥션 안에서 여러 스트림(요청)이 동시에 진행되고, mod_http2는 이들을 스레드 풀로 처리한다: assign_headers()는 응답 헤더를 배정하는 길목인데, 동시 실행되는 스레드들이 같은 공유 자원(헤더 메모리)에 부적절하게 동기화된 채 접근한다 — CWE-662(부적절한 동기화)가 Apache가 공식 붙은 분류다
  • 결과: 힙 손상(heap corruption) — Wiz는 "동시 스레드가 공유 자원을 실행할 때 동기화 부적절로 힙 손상을 유발할 수 있고, 이 메모리 손상이 최종적으로 RCE로 연결돼 웹 서버 프로세스 권한으로 임의 명령을 실행하게 된다"고 분석했다 — 요청 처리 중 자연히 호출되는 함수이므로, 다중 스트림만으로 트리거 가능한 원격 입력 지점이다
  • Red Hat의 대응 근거가 구조를 역설명한다: RHEL 빌드는 스트림별 독립 메모리 할당자를 적용해 두었다 — 공유 힙을 쪼개 놓으면 한 스트림의 손상이 다른 스트림/프로세스 제어 흐름으로 번지기 어렵다 — 즉 결함의 위험성은 '스트림 간 공유 힙'이라는 구현 선택에 비례했고, mitigation도 같은 축(분리)에서 나온다
출처Apache 어드바이저(CWE-662) · Wiz 취약점 분석 · Red Hat severity assessment

패턴 지식: HTTP/2 모듈 결함은 이번이 처음이 아니다 — CVE-2026-23918(5월, 2.4.67 고정)도 같은 모듈이었고, 그 패치를 적용한 서버가 이번 범위(2.4.55~2.4.70)에 다시 포함된다. 멀티플렉싱 코드베이스는 '동기화'라는일종 결함을 반복 생성하는 구조적 취약 지대다. 프로토콜이 복잡해질수록 상태 기계의 교차점이 늘고, 교차점은 곧 경쟁 조건 후보지점이다.

Deep Dive 2

'신뢰할 수 있는 익스플로잇'은
실재하는가 — 진술 충돌 보고서

Red Hat: "기본 구성에서 실증된 신뢰 exploit" · Wiz: "공개 익스플로잇·야생 악용 없음"
쟁점 분석
  • Red Hat 평가(11.11)는 "public research has demonstrated a reliable exploit" — mod_http2가 켜진 기본 구성 서버에 대한 신뢰할 만한 익스플로잇을 공개 연구가 실증했다고 밝혔다 — 다만 그 연구를 지칭·링크하지 않았다 (THN이 지적), Wiz는 같은 날 늦게 "익스플로잇은 없고 야생 악용 보고도 없다"고 반박했다: 두 공식 진술이 정면으로 어긋난 상태다
  • 가장 정합적인 해석은 'PoC 공개 여부'의 차이 — AI 스캐너·연구팀이 내부적으로 트리거를 입증했을 수 있으나(그래야 RCE 등급 부여가 자연스럽다), 그것이 공개 코드나 관측된 악용은 아니다: Apache가 워크어라운드를 제공하지 않는다고 한 것과 Wiz의 '악용 없음'은 양립하고, Red Hat의 문구는 '연구 존재'이지 '유포 중'이 아니다 — 덱는 세 상태를(실증 연구/비공개·공개 익스플로잇 없음·야생 악용 없음) 분리 표기한다
  • 대응 시간 창 계산: 패치 공개 11.11 → 데일리 빌드·스크래퍼가 24시간 내 diff 분석 시작 — 과거 패턴(4EverAble2Shell: PoC 공개 수 시간 내 악용)에 따르면 '패치 후 익스플로잇 개발'이 지금의 최대 리스크 구간이다 — KEV 미등재·야생 무보고는 '창이 아직 열려 있음'의 동의어다
출처Red Hat 평가 · Wiz 분석 · The Hacker News 교차 보도

위기관리 커뮤니케이션 교과서적 사례: 한 CVE에 대해 벤더-평가기관이 상반된 언어를 쓰면, 실무자는 가장 보수적인 축(즉시 패치+임시 강등)으로 수렴해야 한다. 반대로 공포 쪽 과잉도 경계 — '기본 구성에서 장악 가능' 류 headlines은 HTTP/2 기본 off 조건을 잘라낸 표현이다. 확인된 사실은 셋: 악용 관측 없음, 공개 PoC 없음, 그런데 패치 배포 후 시간이 갈수록 창이 좁아진다는 것뿐이다.

Action Items

오늘의 조치 —
Apache 운영자 실행 목록

즉시
HTTP/2 사용 여부 확정 — 서버 전역+모든 가상 호스트의 Protocols 지시자에서 h2/h2c 존재 전수 확인(httpd -M | grep http2, 설정 grep), 미사용 확인 시 mod_http2 로드 해제
기본값은 off — 'Apache 사용'과 '취약'은 다른 명제
즉시
HTTP/2 필수 환경은 2.4.71 즉시 업그레이드, 불가 시 Protocols에서 h2/h2c 제거 후 http/1.1로 강등(성능 손실 감수) — 배포판 사용자: RHEL 9/10 RHSA 적용, Debian bookworm/trixie는 고정 패키지 대기 중이므로 강등 병행
mod_h2 독립 빌드는 상류 패치 없음(아카이브) — 강등 필수
금주
클라우드 자산 재인벤토리 — 공개 노출 인스턴스 중 Apache+HTTP/2 조합 색출(Wiz 통계: 클라우드 64%가 취약 자원 보유, 절반 가까이가 노출), 컨테이너 이미지의 내장 httpd 버전 스캔
JBoss Core Services·Hardened Images는 affected 무패치 목록 확인
금주
공격 표면 모니터링 — WAF/프록시에 HTTP/2 프레임 이상(비정상 CONTINUATION·헤더 폭주) 규칙 추가, httpd 워커 프로세스의 비정상 자식 생성·아웃바운드 연결 EDR 룰 강화
패치 공개 후 diff-to-exploit 창이 현재 최대 리스크 구간
지속
AI 스캐너 시대 패치 SLA 재설정 — 핵심 오픈소스(서버·프로토콜 스택)의 upstream 보안 공지 구독 자동화, AI 발견 CVE 크레딧 추이 관찰(OSS Scanner 류), '공지→패치→악용' 주기가 짧아지는 전제로 긴급 패치 창고(rollback 테스트) 정비

편집 고지본 특집은 Apache HTTP Server 공식 보안 어드바이저(11.11)를 1차 근거로 Red Hat severity 평가·Wiz·watchTowr 분석·The Hacker News·BleepingComputer 보도를 교차 대조했습니다.
