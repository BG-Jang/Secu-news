Top Story 1

Apify 침해 —
AI 데이터 파이프라인의
토큰이 돌았다

11.9~10 비인가 접근 · 11.10 12:13 UTC 탐지 · 내부 자격증명 폐기·세션 강제 종료
확인 사항 (Apify 공식 공지·BleepingComputer)
  • 체코의 웹 스크레이핑·브라우저 자동화 플랫폼 Apify가 11월 9~10일 내부 시스템 일부에 비인가 제3자 접근을 받았다고 공식 발표했다 — 다음 날 12:13 UTC 탐지 직후 공격자 접속 차단, 내부 자격증명 무효화, API 토큰 회전, 활성 세션 강제 종료를 단행했다
  • 예방 조치로 GitHub 등 외부 통합 OAuth 연결을 해제했고(안전 확인 후 재연결 안내 예정), 피해 고객에게는 Apify API 토큰과 프록시 비밀번호가 회전됐다고 통지했다 — 회사는 "플랫폼에 저장된 계정 데이터가 영향을 받았다는 정황은 발견되지 않았다"고 밝히면서도, "2FA 코드가 노출됐을 수 있다"며 콘솔에서 2단계 인증 재설정을 권고했다(비밀번호는 안전하다고 안내)
  • 고객사 8만 곳 — 마이크로소프트·삼성·T모바일·액센추어·지멘스·유럽집행위원회·로슈가 공식열거 목록에 포함 — 생성형 AI 붐과 함께 LLM·에이전트의 실시간 데이터 수집 계층으로 얹혀진 플랫폼이다
출처Apify 공지 · BleepingComputer(11.12) · The Hacker News

정정 1건: 브리핑은 고객사를 '삼성, 지멘스, T모바일, 액센츄어 등'으로 적었지만 공식 목록에는 마이크로소프트와 로슈도 포함된다. 더 중요한 정정은 위험의 성격 — 직접 유출 증거는 아직 없고, 노출 의심 항목은 2FA 시드다. 2FA 시드가 새면 공격자는 비밀번호만으로 2FA를 뚫는다: '비밀번호 안전' 발표와 '2FA 재설정 권고'를 나란히 읽어야 하는 이유다.

Top Story 2

오퍼레이션 엔드게임 —
스틸러 창고를
터뜨리다

C2 서버 235대 압류 · 도메인 257개 무력화 · 탈취 자격증명 640만 건 식별
작전 성과 (Europol·BleepingComputer 11.12)
  • 유로폴·유로저스트 조정 아래 불가리아·캐나다·덴마크·독일·몰도바·네덜란드·폴란드·영국·미국 9개국과 민간 파트너가 합동으로 Gootloader(2020년부터 활동한 로더)·CastleRAT(작년 등장 RAT)·StealC(자격증명·암호화폐 지갑 스틸러)의 인프라를 타격했다 — 세 패밀리 모두 랜섬웨어 조직에 초기 침투 수단을 공급해 온 공급망이다
  • 범죄자 인프라에서 식별된 피해자 데이터셋 640만 건 — 감염 기기에서 훔친 자격증명으로, 암시장에서 판매돼 랜섬웨어 등 후속 공격에 쓰일 예정이었다 — CastleRAT 피해자 데이터는 HaveIBeenPwned·DIVD·CheckjeHack·NoMoreLeaks·Sekoia·Shadowserver·NL-NCSC 플랫폼으로 공개 통지된다
  • 같은 작전의 연속선 — 6월 SocGholish·Evil Corp 서버 106대+WordPress 감염 사이트 1만5천 건 정화, 같은 달 Amadey·StealC 인프라 326개 서버·142 도메인 차단과 자격증명 약 2,700만 건 회수(피해 시스템 38만5천 곳), 1년 전 Rhadamanthys·VenomRAT·Elysium 서버 1,000대 이상 타격
출처Europol 발표 · BleepingComputer(11.12)

'640만 건'은 이번 주 압수분이고, 6월 Amadey·StealC 단계에서 이미 2,700만 건이 회수된 전력이 있다 — 누적 스틸러 피해 규모가 얼마나 거대한지의 척도다. 기업 실무 관점: 임직원 이메일이 HaveIBeenPwned 등에 올라있다면 그건 구식 유출이 아니라 '현재 유통 중인 열쇠'일 수 있다. 패스워드 교체+MFA 재등록이 필요하다.

Top Story 3

SCKit —
지원 기사님을 노린다:
세션 하이재킹의 완성형

Blackpoint Cyber APG 포착 · CVE-2026-84869(CVSS 9.9, 이미 패치·KEV 등재) 경유
공격 메커니즘 (The Hacker News·Blackpoint Cyber)
  • SCKit은 새 취약점이 아니라 이미 패치된 CVE-2026-84869(부적절한 권한 관리·승인 누락, CVSS 9.9 — guest 세션에서 호스트 확인 없이 파일 전송·실행)를 쓰는 툴킷이다 — 공격 시퀀스는 플랫폼 내장 Run Command로 기존 ScreenConnect 설치 확인 → 공격자 MSI('sc.msi') 다운로드 실행 → 배치 드로퍼('sckit-run.bat') → 'ns.mo7sen[.]dev'에서 PowerShell 디코더('sckit-decoder.ps1') 수신
  • 무단 ScreenConnect Access 클라이언트 2개를 심어 영속 원격 제어를 확보하고, RelayTrap 컴포넌트로 지원 연결을 요격한다 — 감염 엔드포인트를 조사하러 온 기술자의 워크스테이션을 역방향으로 감염시키는 '역시도(reverse-pivot)' 기능
  • 기술자 기계에서 로컬 브라우저 데이터·프로세스 메모리를 뒤져 인증된 관리 세션(.ASPXAUTH 쿠키)을 탈취, 자격증명 없이 그 기술자가 관리하는 다른 고객 엔드포인트로 명령을 배포한다 — 기존 에이전트를 통해 NT AUTHORITY\SYSTEM 권한으로 소프트웨어 배포까지 수행 — 악용된 CVE는 9월 11일 CISA KEV 등재(연방 패치 기한 9월 14일), 과거 XMRig 채굴 유포에 쓰인 것과 같은 결함이다
출처The Hacker News(11.12) · Blackpoint Cyber APG

정정 2건: 브리핑은 '활성 세션 토큰을 메모리에서 가로채는 신종 기법'으로 서술했지만, 실측은 '패치 안 한 CVE-2026-84869로 발판 → 기술자 역감염 → 세션 쿠키 탈취'의 3단 구조였다. 토큰 가로채기는 진입 후 두 번째 단계다. 핵심 교훈은 패치 격차 그 자체 — KEV 등재 두 달 반이 지나도 미패치 엔드포인트가 공격면을 제공한다.

Deep Dive 1

토큰이 새는 계층 —
Apify 사태가 보여주는
AI 공급망의 지오메트리

구조 분석
  • Apify는 '데이터 수집 SaaS'이지만 실질 기능은 세 겹이다: 고객 네트워크 내부로 나가는 프록시 자격, GitHub 등 코드 저장소와 맺은 OAuth, 그리고 에이전트 워크플로우를 실행하는 API 토큰 — 이번 회수는 세 겹을 한꺼번에 돌렸다 — SaaS 하나 침해에 연쇄 재인증이 필요한 이유가 이 결합도에 있다
  • 위험의 본사는 유출보다 무결성이다: LLM 에이전트가 크롤링 결과를 그대로 학습·판단 재료로 삼는 구조에서, 탈취한 토큰으로 파이프라인에 허위 데이터를 주입하면(Data Poisoning) 기업 AI는 오염된 입력으로 의사결정한다 — 탐지가 거의 불가능한 2차 피해다
  • 연속 사고 문법 — Fireworks AI(클라우드 경유)·mSecure 비밀번호 관리자·OpenCode API 키 유출 등 'AI 인프라 자격증명' 사고가 올해 나란히 쌓였다: 모델 자체를 뚫지 않아도, 모델에게 먹이는 통로와 통로의 열쇠를 뚫면 된다 — 에이전트 시대 공급망 실사의 대상은 벤더 소프트웨어가 아니라 벤더가 가진 우리 명의의 자격이다
출처BleepingComputer 보도 종합 · Apify 공지

Apify 고객 중 AI 파이프라인에 이 플랫폼을 쓰는 팀은 오늘 두 가지를 해야 한다: 회수된 토큰으로 도는 자동화가 살아있는지(깨진 통합 방치=우회 경로), 그리고 그 자동화의 출력이 어떤 판단에 쓰이는지. '토큰 회전'은 회사 측 조치일 뿐, 의존성 목록은 각 기업이 직접 그려야 한다.

Deep Dive 2

세 개의 구멍, 하나의 문법 —
'합법 자격'의 무기화

Apify 내부 토큰 · 스틸러 자격증명 뱅크 · ScreenConnect 관리 세션
쟁점 분석
  • 오늘 세 기술 사안은 겉보기 플랫폼이 전혀 다르지만 동일 문법을 쓴다 — 악성 코드 주입 없이, '이미 신뢰된 자격'으로 경계를 통과한다: Apify는 내부 시스템에 도달한 자격증명 폐기로, 엔드게임은 훔친 640만 개 로그인으로, SCKit는 승인된 원격 지원 세션과 .ASPXAUTH 쿠키로 움직인다
  • 방어의 대응 단위도 같아진다: 경계 차단이 아니라 자격의 수명 관리 — 단기 토큰·세션 즉시 만료·권한 최소화가 Apify에는 회수 조치로, 기업에는 "원격 지원 세션 종료 즉시 자격 만료" 권고로, 스틸러 대응에는 MFA 재등록으로 각각 번역된다
  • 그리고 어제의 금보원 사고까지 같은 축에 선다 — 위조 금감원 계정은 '승인이라는 자격 발급 절차'를 통과한 공격이었다: 네 사고를 관통하는 질문은 하나, "당신 시스템이 신뢰하는 자격의 발급·검증·회수 주기는 누가, 언제 검증했는가"
출처BleepingComputer · Europol · Blackpoint Cyber · 금융보안원 사고 보도 종합

'identity-first 보안'이 슬로건에서 실무가 되는 지점이다. EDR은 악성을 잡지만 유효 세션은 못 잡는다 — 이상 시간대 관리 접속, 세션 수명 이탈, 지원 도구 프로세스의 아웃바운드 패턴처럼 '자격의 행동'을 감시하는 룰이 이번 주 모두의 공통 액션 아이템이다.
