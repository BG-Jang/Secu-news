Top Story 1

NGINX2Root —
11년 잠복 HTTP/2 결함,
948만 대의 오늘

CVE-2026-123007(CVSS 4.0 9.2) 포함 치명 5종 · 패치율 1% 미만 · 배포판 패키지 미배포
  • F5 공식 릴리스(11.18): NGINX 오픈소스 1.30.7·1.31.9, NGINX Plus 37.3.0.1·37.0.8.1 — 총 10개 CVE 수정, 그중 RCE 결함 5종 — 핵심은 2015년 1.9.5의 HTTP/2 도입 이래 존재한 흐름 제어 버그: WINDOW_UPDATE+RST_STREAM 조합으로 전송 윈도우 크레딧을 중복 반환 → 정수 오버플로·메모리 손상
  • Censys 스캐닝 기준 약 948만 개 서비스가 취약 버전에서 HTTP/2 활성 상태로 노출 — 패치율 1% 미만 — Debian·Ubuntu·RHEL·SUSE 패키지 미배포, 커뮤니티 ingress-nginx는 2026년 3월 은퇴되어 공식 패치가 없다: nginx 1.30.7/1.31.9 공식 바이너리·도커 이미지 교체(완전 재시작, reload 불가) 또는 http2 off; 가 우선
  • 체이닝 위협: 백엔드 프록시 Use-After-Free CVE-2026-123633('Drainbreak')은 Kong·Apache APISIX·OpenResty·NGINX Gateway Fabric에서 크래시 확인 — 워커 권한 확보 후 2018년부터 미패치인 Linux 커널 SCTP 모듈 UAF를 연쇄하면 도커 컨테이너 안에서 호스트 root까지 도달 — Rapid7이 로컬 검증용 PoC를 GitHub 공개, Precursor Security 트래커에 상세
출처The Hacker News · Precursor Security 트래커 · Rapid7 PoC · Censys 노출 집계

탐지 불가능성이 이 결함의 무서운 지점: 개별 HTTP/2 프레임이 전부 규격에 부합하므로 기존 WAF·IDS 시그니처가 못 잡는다. 방어는 회피가 아니라 제거뿐 — ① 인터넷 노출 리스너 http2 off; ② 호스트에서 SCTP 모듈 차단(modprobe.d blacklist)해서 컨테이너 탈출 사다리 제거 ③ ingress-nginx처럼 '은퇴했지만 아직 돌아다니는' 구성의 소유자를 오늘 특정할 것. 배포판 패키지 나올 때까지가 공격자의 창이다.

Top Story 2

Java4Shell D-Day —
어제의 '추정'이 패치가 됐고
자바 공화국이 긴다

CVE-2026-114938(3.1 8.1 / 4.0 9.2 보고) 패치 배포 · CISA 즉시 권고 · 공공 시스템 71.28% 자바
  • Oracle·OpenJDK가 11월 18일(한국시간) 패치 배포, 미국 CISA가 즉시 패치 촉구(KISA 보호나라 공지 병행) — 어제 호에서 'RCE 대 DoS 양론 진행 중'으로 표기했던 결함은 Base64 디코더(avx512vbmi 가속 Intrinsics)의 out-of-bounds write 메모리 손상으로 정리: OpenJDK 17.0.6 이상(21·25 포함) x86-64 + AVX-512 노출 환경에서 특수 Base64 입력만으로 JVM 크래시~무인증 RCE
  • 국내 파급력: 행안부 통계 기준 공공 정보시스템 15,618개 중 71.28%(11,132개), 중앙행정기관 시스템의 89.05%가 자바(전자정부 표준프레임워크 등) 기반 — PHP2Shell 당시 공공 비중 6.58% 대비 10배 이상 — 국정원·과기정통부·KISA 긴급 점검 돌입(보안뉴스), Jira·Jenkins·Keycloak 등 엔터프라이즈 미들웨어가 영향권
  • AI 무기화 속도의 실측치: 제보자 Calif는 AI 보조로 1시간 만에 버그 발견, 200달러 미만 토큰 비용으로 2시간 만에 익스플로잇 작성(TuxCare 분석) — 임시 완화: -XX:UseAVX=2로 AVX-512 제한, SSO·GPKI·DRM 등 벤더 번들 JDK 내장 상용 솔루션의 런타임 전수 식별
출처The Hacker News · 보안뉴스(국내 점검) · KISA 보호나라 · TuxCare 분석

어제 호 편집 고지의 '미확보 항목' 두 개(CVE의 CSPU 포함 여부, RCE 실체)가 하루 만에 해소된 것은 이례적으로 빠른 코디네이션이다. 남은 리스크는 패치 자체가 아니라 도달 범위: 번들 JDK를 숨긴 상용 패키지(벤더 JVM 업데이트를 기다려야 하는 것)가 국내 공공·금융에 많다는 점 — 어제 권고한 JVM 인벤토리가 오늘 바로 그 목록 작업으로 전환된다.

TPM 잠금 우회 —
케이스를 열면
PIN 자물쇠가 초기화된다

6자리 BitLocker PIN 6분 55초(236회) 해제 · 4자리 Hello PIN 57분 · Winbond 칩은 재설계 필요
  • TU Berlin 연구진: 프로세서 내장 fTPM은 자체 비휘발성 보안 저장소가 없어 오입력 횟수 상태를 메인보드 SPI 플래시 칩에 암호화 저장 — AMD PC(CVE-2026-43613)는 펌웨어가 RPMC 카운터 실제 증가를 검증하지 않아, 중간 인터포저 보드로 업데이트를 가로막으면 잠금 횟수가 초기화(The Hacker News)

하드웨어 신뢰의 약한 고리는 늘 '물리'였다: fTPM의 보안은 플래시 칩과의 통신을 누가 가로채느냐에 걸려 있었고, 그 채널은 케이스 안의 보드 위 배선이다. 도난 피해 시나리오가 '암호학적으로 안전'했던 PIN 체계를 '물리적으로' 무너뜨린다 — laptop 자산의 BitLocker 정책 재점검, 그리고 PIN 복잡도보다 먼저 '분실·도난 시 원격 잠금(MDM)'이 실제 작동하는지 확인이 필요하다.

KISA 대민 웹
일주일째 먹통

Apache Roller CVE-2026-129448(9.8) 야생 악용 확인 · Puppet CVE-2026-115731(9.4) KEV 등재

'관리 도구'와 '신고 채널'이 동시에 무너진 오늘의 공통분모는 신뢰 인프라의 단일 장애점이다: Puppet은 뚫리면 전 fleet이, KISA 대민 웹은 멈추면 신고·인증 행정 전체가멈춘다. 자사 기준 질문: 이 정도 급 정지를 감행할 만큼 우리도 점검 중인가, 아니면 점검 자체를 못 하고 있는가.

Deep Dive 1

NGINX2Root 해부 —
규격에 맞는 프레임만으로
메모리를 무너뜨린다

  • 프로토콜 논리 결함의 전형: 각 WINDOW_UPDATE·RST_STREAM 프레임은 HTTP/2 규격에 정확히 부합한다 — 결함은 두 프레임의 '순서 조합에 따른 크레딧 회계'라는 상태 머신에 있었다 — 바이트 패턴 기반 WAF·IDS가 구조적으로 잡을 수 없고, 프로토콜 스택 자체의 크기 제한·상태 검증이 유일한 방어다(F5는 스택 내부 수정으로 대응)
  • AI 발굴의 이정표: 발견자 중 하나 Xint는 OpenAI 모델 기반 AI 에이전트로 NGINX 코드 5만 줄을 90분 분석해 치명 결함 4개를 인간 개입 없이 찾아냈다고 밝혔다 — 어제 GTIG의 '패치→무기화 수시간' 경고와 같은 축: 이제 '10년간 아무도 발견한 버그'는 AI에게 하루면 나오는 버그다. 공개 전 잠복 기간이 안전기간이라는 가정이 소멸했다
  • 노출 산정의 교훈: 948만 서비스 중 패치율 1% 미만 + 배포판 패키지 미배포 + ingress-nginx 은퇴(2026.3) — 기술적 패치가 있어도 공급 경로가 막히면 실질 패치는 안 된다 — 컨테이너 베이스 이미지의 nginx는 '배포판을 거치지 않고' 직접 들어간 경우가 많아, 이미지 태그 재빌드가 배포판 패치보다 빠르다
출처Precursor Security 트래커 · The Hacker News · Censys · Xint 발표

공격 체인을 시간축으로 놓으면: 노출(948만) → PoC 공개(Rapid7, 이미 끝남) → 배포판 패치(미정) → 그 사이 창. 오늘 실행 단위는 'http2 off 전환 가능 목록'과 'SCTP blacklist 적용 목록' 두 개뿐이다 — 둘 다 재시작을 요구하므로 변경 관리가 필요하지만, WAF를 믿는 선택지는 이번 결함에서는 존재하지 않는다.

Deep Dive 2

'자바 공화국'의 청구서 —
89.05%가 물려 있는
런타임 하나의 리스크

공공 정보시스템 71.28% 자바 · 중앙부처 89.05% — 표준프레임워크 단일 스택의 효율과 집중 리스크
  • 전자정부 표준프레임워크 중심의 단일 언어 스택은 조달·인력·유지보수 효율의 산물이지만, 런타임 결함 하나에 국가 행정 전체가 동시 노출되는 집중 리스크의 다른 이름이다 — PHP2Shell(공공 6.58%) 때 10배 이상의 표면: 이번 주 Java4Shell은 '표준화의 이자'가 언제든 사고로 청구될 수 있음을 실증한다
  • 대응 병목의 실제 지점은 오픈소스 JVM이 아니라 번들 JDK: SSO·GPKI·DRM 등 상용 솔루션에 내장된 벤더 JVM은 벤더 패치를 기다려야 하고, 그 대기가 곧 미패치 창 — 어제 권고한 jcmd·컨테이너 인벤토리가 오늘 '번들 JDK 자산 목록'으로 구체화된다: 어떤 시스템이 몇 버전을 내장 중인지가 모르면 패치 지시 자체가 불가능하다
  • AI 보조 발견의 경제학(Calif 실측): 발견 1시간 + 익스플로잇 작성 2시간 + 토큰 비용 200달러 미만 — 벤더 코디네이티드 공개(어제 유출 파문→오늘 패치)가 하루 만에 끝난 것도, 공격자의 재현 속도가 하루 단위이기 때문이다 — 방어 측 '전수 점검' 지시가 행정 절차로 수 주 걸리는 구조와의 속도 격차가 이번 사안의 본질

Deep Dive 3

무너진 세 개의 '블랙박스 신뢰' —
TPM·SCTP·표준프레임워크가
가리키는 같은 교훈

  • 오늘 세 사안의 공통 구조: '하드웨어/커널/표준이 알아서 지켜줄 것'이라는 검증되지 않은 가정 — TPM 잠금은 플래시 칩과의 물리 채널을 신뢰했고, 컨테이너 격리는 8년 전 미패치 SCTP를 남긴 호스트 커널 위에 서 있었으며, 공공 스택은 단일 런타임의 무결성을 신뢰했다. 세 경우 모두 신뢰 경계 안의 결함은 감사 대상에서 빠져 있었다
  • 수리 불가능한 결함이라는 새 카테고리: Winbond RPMC 칩은 재설계가 필요해 펌웨어로 못 고친다 — '언젠가 패치된다'가 성립하지 않는 자산이 존재한다(AMD는 2027년 2월까지 순차 패치) — 하드웨어 수명주기 동안 방어 심도를 올려야 한다: PIN 길이·복잡도 상향, 분실 시 원격 잠금, 그리고 '물리 접근을 전제로 한' 위협 모델로의 전환
  • AI는 이 모든 것을 압축한다: 90분에 NGINX 5만 줄, 1시간에 버그·2시간에 익스플로잇 — 발견 속도가 무한이 되면 '오래된 코드=검증된 코드'라는 잠언도 성립하지 않는다 — 남는 방어의 원칙은 하나: 신뢰를 객체화하고 검증 가능하게 만드는 것(SBOM·서명·무결성 감시·이그레스 통제)이 곧 이번 주 세 교훈의 합집합이다
