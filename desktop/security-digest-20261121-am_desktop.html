Top Story 1

AI 에이전트가
제로데이를 찾아
11분 만에 root를 잡았다

Cairn에 부여된 목표는 단 하나 '셸 접근' — 인간이 몇 주 걸던 제로데이 발굴·무기화가 10여 분 단위로 압축
  • Amazon Threat Intelligence 공개: 공격자가 오픈소스 멀티에이전트 침투 도구 'Cairn'(비인증 노출로 정찰 기록이 유출된 상태)에 셸 획득 목표만 부여 — 에이전트가 동아시아 대학 연구기관의 오픈소스 의료 영상 AI 앱 MONAI Label에서 미지의 경로 탐색 제로데이를 스스로 발견, API 매핑부터 Python 시작 스크립트(sitecustomize.py)에 리버스 셸 심기까지 11분 만에 root 장악(MONAI Label은 11월 18일 패치 배포)(BleepingComputer)
  • 같은 날 Bell Canada 공식 인정: 11월 17일 '에이전틱 위협 행위자'가 통신 회선 주문·프로비저닝용 Maximo 사전 운영(Pre-production) 환경에 침입 — 기업 고객 연락처, 티켓 제목, 일부 네트워크 IP 정보가 탈취됐다. 통신 인프라의 '개발·스테이징' 영역이 정면 표적이 된 첫 대형 공식 사례
  • 두 사건의 공통분모는 속도 압축과 방어 허점 이동 — 프로덕션보다 인증·망분리가 약한 사전 운영 환경, 그리고 인간 분석가가 따라갈 수 없는 속도의 API 탐색. 개발·스테이징 환경을 프로덕션 동급으로 격리하고 비정상 고속 탐색을 차단하는 자동 방어가 시급하다
출처BleepingComputer · Amazon Threat Intelligence · Bell Canada 공식 확인

표현 주의: Cairn 공격의 배후 '중국 연계 추정'은 보도 기준 추정 표기다. Bell Canada는 공격자를 '에이전틱 위협 행위자'로만 표현했으며 국가·조직 귀속은 미확인. '11분'은 Amazon 발표 기준 실측으로, 에이전트 무기의 반응 시간을 전제로 한 방어 SLA 재설계(인간 대응 창 24시간 → 자동 차단 분 단위)가 실무 논점으로 떠오른다.

Top Story 2

게스트가 호스트를 읽는다 —
KVM 격리 붕괴와
'패치가 만든 구멍'

CVE-2026-99312 (커널팀 채점 CVSS 8.8 High) — 게스트 VM root가 호스트 RAM 127GB 열람·호스트 커널 메모리 변조
  • 원인은 '패치가 만든 취약점': 2022년 CVE-2022-3344를 고치던 보안 패치가 중첩 VM의 INIT 리셋 때 외부 VM의 중첩 페이지 테이블(NPT) 포인터 복구를 누락 — 이후 약 4년간 커널에 잠복했다. NVD 수정 커밋은 'KVM: x86: Unconditionally reset MMU context when emulating INIT' — INIT 에뮬레이션 시 페이징 여부와 무관하게 MMU 컨텍스트를 강제 리셋하도록 된다
  • 공격 구조: 게스트 VM 내 root 공격자가 해제된 페이지 메모리에 조작된 페이지 테이블 엔트리를 채우면 CPU가 이를 정상 테이블로 인식 — DigitalOcean 공유 클라우드 등 AMD 호스트에서 Terra Security 연구원 Oren Yomtov가 검증. Intel 호스트는 해당 코드가 없어 영향 없음
  • 업스트림은 수정 완료(7.3.5·6.18.64·6.12.118), Debian·Ubuntu·RHEL 배포판 패키지는 아직 미배포 — 게스트 OS 패치로는 막을 수 없고 호스트 커널 업데이트 후 재부팅이 필요하다. 그 전까지 중첩 가상화가 불필요한 AMD 호스트는 kvm_amd nested=0 + 재부팅이 유일한 차단책
출처The Hacker News · NVD API(CVE-2026-99312 커널팀 채점 8.8) · Terra Security 검증

NVD 원문 확인: 상태 Received, CVSS 3.1 8.8 High(커널팀 채점), KEV 카탈로그(2026.11.20 기준) 미등재 — '악용 보고 없음' 상태로 공개됐다. 그러나 성격이 하이퍼바이저 격리 붕괴라 멀티테넌트 클라우드 사업자에게는 점수보다 훨씬 무거운 사안이다. 어제 NoisyTCP(네트워크 스택), 그제 NGINX2Root(웹서버)에 이어 인프라 하부 결함 3연타의 마지막 조각.

Top Story 3

Expressway가 뚫렸다 —
PoC 공개 직후 야생 악용,
AI 작성 스크립트로 횡적 이동

CISA KEV 11월 20일 등재 · SSVC 악용 'active'·기술적 영향 'total' — 경계 장비 root 탈취는 내부망 전체의 문제
  • Cisco Expressway Series X15.5.3 이하: 영구 쿠키 사용 + 클러스터 TLS 클라이언트 인증서 검증 미흡으로 무인증 원격 공격자가 DB 서비스 RPC를 호출해 OS root 명령 실행(CVE-2026-76466, Cisco 원채점 9.8) — 10월 21일 패치(X15.5.20 등) 이후 러시아 보안 기업 F6가 PoC 공개 직후 첫 야생 공격을 포착했다(The Hacker News)
  • 공격 체인: 인터넷 노출 장비 2대 장악 → 클러스터 신뢰 관계를 타고 내부 노드 2대로 피벗 → SMB·SQL Server·WinRM·내부 GitLab 저장소를 AI 도구로 작성한 것으로 추정되는 Python 스크립트들로 자동 탐색·자격증명 탈취 — '경계 장비 1대 = 내부망 스캐너 배치'라는 고전 패턴이 AI 자동화로 재등장했다
  • 점검 지침: Erlang 로그(erlang.log)의 wombat@127.0.0.1 흔적, /mnt/harddisk/ 경로 비인가 Python 스크립트 유무 확인 — 패치 미완료 장비는 즉시 X15.5.20 이상으로, 당장 불가하면 인터넷 노출을 해제해야 한다
출처The Hacker News · F6 발표 · NVD(Cisco psirt 채점) · CISA KEV 2026.11.20

확인 사실: KEV 등재일 2026-11-20, SSVC exploitation 'active' — 어제까지의 CVE 보도들과 달리 이 건은 '실제 악용 확인' 축에 속한다. Expressway는 화상회의 경계 장비로 외부와 내부망을 동시에 보는 위치에 있어, 클러스터 신뢰를 통한 피벗이 특히 치명적이다. AI 작성 스크립트 정황은 F6 분석 기준으로 '추정' 표기.

Deep Dive 1

11분이라는 숫자가
바꾸는 것 —
에이전틱 해킹의 작전학

  • Cairn 사건의 본질은 '목표 위임'이다: 공격자는 익스플로잇을 고르지 않았다. "셸을 얻어라"는 목적 함수만 던졌고, 표적 선정·API 매핑·제로데이 발견·sitecustomize.py 백도어 심기까지 에이전트가 계획하고 실행했다 — 공격의 기술적 진입 장벽이 '익스플로잇 개발 능력'에서 '에이전트 운영 비용'으로 이동한 것. 저숙련 공격자도 대량 병렬로 제로데이 복권을 살 수 있게 된다
  • MONAI Label 같은 AI 연구 스택이 표적이 된 것은 구조적이다: 연구·교육 환경은 노출은 넓고 감시는 얇으며, 오픈소스 ML 도구는 의존성 그래프가 깊다 — 에이전트는 이 '감시의 사각'을 인간보다 빠르고 지치지 없이 훑는다. 어제 다룬 진트(Xint)의 NGINX2Root 자율 탐지와 같은 축에서 읽어야 한다: 발굴 속도의 방어·공격 동시 가속, 이른바 'AI 대 AI' 군비 경쟁이 실전 단계에 진입했다
  • Bell Canada가 보여준 두 번째 교훈은 환경 격리의 실패다: 공격자는 프로덕션이 아니라 Maximo 사전 운영(Pre-production) 환경을 골랐다 — 에이전틱 공격에게 Dev/Stage는 '동일 기능·약한 방어'의 최적 경로다. 대응 원칙은 단순하다: 사전 운영 환경에 프로덕션과 같은 인증·망분리·감시를 적용하고, 고속 API 탐색 패턴(단위 시간당 엔드포인트 접근 폭증)을 탐지 규칙으로 상시화하는 것
출처Amazon Threat Intelligence · BleepingComputer · Bell Canada 발표 종합

실무 체크: ① 연구·내부 도구가 쓰는 오픈소스 ML 스택(MONAI Label 등)의 인터넷 노출 전수 조사 ② sitecustomize.py·.pth·site-packages 자동 로드 지점 무결성 감시 — 에이전트가 가장 선호하는 '재기동 시 자동 실행' 위치 ③ Dev/Stage 환경 SSO·MFA 적용 여부 감사 ④ API 게이트웨이 레벨에서 봇/고속 탐색 속도 제한.

Deep Dive 2

경계 장비 한 대가
내부망 스캐너가 된다 —
AI 스크립트 횡적 이동 해부

  • Expressway 침투의 2단계는 '신뢰 구조 타기'였다: 공격자는 내부 노드를 뚫지 않았다 — 클러스터 노드 간 TLS 클라이언트 인증서 검증 미흡을 이용해 같은 클러스터 노드 2대로 피벗 — 경계 장비의 고질병이 또 재현됐다: 밖을 보는 인터페이스와 안을 보는 인터페이스가 한 기기에 있고, 안쪽 신뢰는 평시에는 편리함이지만 전시에 통로다. 방화벽 정책상 '관리 프로토콜 허용'으로 열려 있던 경로가 공격자의 내부 진입로가 된다
  • 3단계의 AI 스크립트: SMB·SQL Server·WinRM·내부 GitLab을 훑는 커스텀 Python 정찰 도구들을 AI 도구로 작성한 것으로 추정 — 과거라면 공격자가 준비해 온 도구가 전부였지만, 지금은 침투한 환경의 출력에 맞춰 그 자리에서 도구를 재생성한다. 탐지 관점에서 무서운 지점: 시그니처가 없는 일회성 스크립트라 파일 기반 탐지가 무력하고, '정상 관리 트래픽처럼 보이는 프로토콜 조합'(WinRM·SMB)을 쓴다
  • 방어 재배치: ① 경계 장비(Expressway·VPN·방화벽·SD-WAN)를 내부망 '신뢰 노드'에서 격하 — 클러스터 신뢰·관리망 접근을 최소로 ② 세그먼트 간 East-West 가시성 확보 — Expressway 세그먼트에서 SMB/WinRM 트래픽은 그 자체가 이상 신호 ③ GitLab 등 내부 저장소의 토큰·시크릿 스캐닝 상시화 — 정찰의 최종 목적이 자격증명이라는 점을 잊지 말 것
